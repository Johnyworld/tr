# 가방 (설계·구현 12-358, 2026-11-27)

좀보이드처럼 가방마다 용량과 무게 감소율이 있고, 등 칸에 멘 가방만 안의 무게를 줄인다. 가방은 내용물째 옮겨지고(바닥·창고·남에게), 다시 주우면 내용물도 그대로다 (계승한 주인공이 앞 주인공의 배낭을 주워도).

## 사용자 결정

1. 가방 속 물건을 넣고 꺼내는 데 시간이 들지 않는다 (창고·장비 칸과 같다)
2. 가방을 바닥에 내려놓으면 내용물째 내려놓이고, 다시 주우면 내용물째 주워진다. 그래서 같은 가방 둘도 각각 따로다
3. (2번으로 풀림) 가방이 소지품을 떠나면 내용물도 함께 간다
4. 바닥은 창고와 같은 방식: 캐릭터 시트에 지금 자리의 바닥 칸, 줍기·내려놓기
5. 수치는 아래 표대로 (넉넉하면 플레이 테스트를 보고 줄인다)
6. 손수레는 이번에 넣지 않는다

## 규칙

- 가방마다 용량(kg)과 무게 감소율(%)이 있다 (아이템 `bag: { capacity, reduce }`)
- 장비에 **등 칸**(`back`)이 생긴다. 등에 멘 가방 하나만 안의 무게가 감소율만큼 준다. 메지 않은 가방에도 넣을 수 있지만 무게는 그대로다
- 가방 자체의 무게는 늘 그대로 센다
- 용량을 넘게 넣을 수 없다. 가방에 가방은 넣지 못한다
- 지금의 `carry_bonus`(배낭 틀 +6)는 없애고 배낭 틀도 가방이 된다. 짐을 나르는 개는 그대로

| 가방 | 용량 | 감소율 | 무게 | 가득 메면 짐에 셈 | 나오는 곳 |
|---|---|---|---|---|---|
| 장바구니 | 5kg | 10% | 0.2 | 4.7kg | 마트, 장터 |
| 숄더백 | 6kg | 20% | 0.4 | 5.2kg | 구시가, 아파트 |
| 책가방 | 8kg | 40% | 0.6 | 5.4kg | 캠퍼스, 아파트 |
| 배낭 틀 | 12kg | 50% | 1.5 | 7.5kg | 만들어 씀, 마트 |
| 등산 배낭 | 15kg | 70% | 1.2 | 5.7kg | 휴게소, 떠돌이 잡화상 |
| 군용 배낭 | 18kg | 80% | 2.0 | 5.6kg | 초소, 교도소 (드묾) |

## 데이터 구조 (C안: 가방이 내용물을 가진다, 사용자 결정 2026-11-27)

- **가방 개체**: `state.bags: { [bagId]: { item, at, contents, worn? } }`. 내용물은 가방만 가진다 (그 자리 소지품에는 가방 물건 하나만 센다)
  - `at`: 가방이 있는 곳 (캐릭터 id, 장면 바닥, 구역 바닥 자리, 창고)
  - 가방을 옮기면 `at`만 바뀐다. 압수·유해·계승·바닥·창고 모두 가방만 옮기면 내용물이 따라간다
- **개체는 안에 무언가 들었거나 메고 있을 때만 있다.** 빈 가방은 그냥 물건이다. 빈 가방에 넣거나 메면 그때 생기고, 비우고 벗으면 사라진다
- 어느 가방이 옮겨 갔는지: 화면·도구가 집으면 이벤트에 `bagId`. 없으면(압수·이야기) 빈 것부터, 다음은 든 것, 멘 것은 맨 나중
- 가방이 나갈 곳 없이 없어지면(망가짐·잃음·바침) 내용물은 그 자리 소지품에 쏟아진다 (리듀서가 이벤트마다 맞춘다)
- `state.bags`는 가방 모듈(`rules/bags.ts`, 공통 규칙 26)과 리듀서만 읽는다

## 가방 속 물건을 쓸 때 (관문)

- 지닌 가방 속 물건도 "가진 것"이다. 필수품·도구 보정은 가방 속에 있어도 붙는다 (꺼내지 않는다)
- 실제로 쓰는 곳(물건 쓰기·치료 물건·덫·라이터·정수 알약·제작 재료·고치기 재료·남에게 주기)은 엔진이 **가방에서 꺼내 쓰고, 남은 것은 다시 넣는다** (사용자 결정)
  - 물병을 마시면 빈 물병이 같은 가방에 돌아가고, 라이터를 켜면 라이터가 돌아간다. 남에게 준 것은 돌아가지 않는다
  - 결과에 "가방(군용 배낭)에서 물병을 꺼냈다", "빈 물병을 가방에 다시 넣었다"를 싣고, **GM이 서술한다**: "한소진은 가방에서 물을 꺼내 마셨다 … 물병을 가방에 다시 집어 넣었다"
- 그 밖에 물건이 줄어드는 곳(탄약, 이야기의 잃음, 거래)은 맨몸에 모자라면 리듀서가 지닌 가방에서 덜어 낸다 (멘 가방은 맨 나중)
- 무기·입은 옷은 가방에 넣으면 벗는다 (손에 든 채로 가방에 넣지 못한다)

## 무게

- 짐 = 맨몸 소지품 무게(가방 물건 포함) + 지닌 가방 속 무게 (등에 멘 가방은 × (1 − 감소율))
- 들 수 있는 무게 = 12kg + 근력 1당 4kg + 짐 나르는 개 (배낭 틀 몫은 빠진다)

## 상태 화면

- **아이템을 누르면 팝오버**: 어디에 둘지 고른다
  - 맨몸 소지품의 물건: 입기·들기(입을 수 있으면), 가방마다 "○○에 넣기"(빈 가방도), 바닥에 내려놓기, 창고에 넣기(거점·거처일 때)
  - 가방 속 물건: 꺼내기(맨몸으로), 다른 가방에 넣기, 바닥, 창고
  - 용량을 넘는 가방은 꺼져 보이고 까닭이 나온다
  - 가방 자체: 메기·벗기, 바닥에 내려놓기(내용물째), 창고에 넣기(내용물째)
- **캐릭터 시트 아래쪽**, 창고처럼:
  - 가방마다 한 칸: "등: 군용 배낭 · 11.2/18kg · 무게 80% 줄임", 메지 않은 가방은 "(메지 않음, 무게 그대로)"
  - **바닥 칸**: 지금 자리의 바닥 물건, 줍기. 바닥의 든 가방은 "군용 배낭 (안에 11.2kg)", 주우면 내용물째
  - 장면에 적대하는 상대가 있으면 화면에서 줍기·내려놓기를 막는다 (GM이 transfer_item으로)
- 줍기·꺼내기는 창고와 같이 너무 무거워지면 막는다 (들 수 있는 무게 × 1.5)

## GM

- 상태의 짐 줄에 가방: "등: 군용 배낭 11.2/18kg (80% 줄임)"
- `stash` 도구에 `pack`·`unpack`(가방에 넣기·꺼내기), `transfer_item`에 `bag`(그 가방째)
- 바닥 물건 줍기·내려놓기는 지금처럼 `transfer_item`

## 늘어나는 것 (복잡도)

- 장비 칸 하나(등), 아이템 칸 하나(`bag`), 상태 칸 하나(`bags`), 리듀서: 가방 옮김(연결만)·쏟기·모자란 몫 덜기
- 가방 모듈 하나(무게·넣기·꺼내기·고르기·꺼내 쓰고 넣기), 관문 십여 곳
- 상태 화면: 팝오버, 가방 칸, 바닥 칸, HTTP 둘(가방, 바닥)
- 세이브 형식 올림. `carry_bonus` 없앰 (배낭 틀 → 가방)

## 순서

1. core: 아이템 `bag`, 등 칸, `state.bags`와 리듀서, 가방 모듈, 무게, 테스트
2. 도구: stash pack·unpack, transfer_item bag, GM 상태 줄
3. 상태 화면: 팝오버, 가방 칸, 바닥 칸, HTTP
4. 콘텐츠: 가방 여섯, 배치, 배낭 틀 바꾸기
5. 검사·테스트, 개발 기록
