# 배포 검토 (초안)

2026-11-17에 나눈 배포 논의를 정리한 문서다. **아직 결정·구현하지 않았다.** 나중에 다시 검토하고, 정해지면 기획서(`docs/design.md`)에 옮긴다.

## 1. 목표와 범위

- 사용자는 MCP를 설치해 자기 에이전트(Claude Code, Claude 데스크톱 등)를 GM으로 삼아 게임을 한다.
- 엔진은 사용자 PC에서 돌고, LLM 비용은 사용자의 구독으로 나간다. 우리 서버는 없다.
- GM 지침은 MCP 안(`play` prompt, `get_gm_guide` tool)에 있어서 MCP만으로도 플레이할 수 있다.
- **범위 밖**: claude.ai 웹·모바일. 로컬(stdio) MCP를 쓸 수 없어서 원격 MCP가 필요하다 (7장).

## 2. 배포 구성

| 클라이언트 | 배포물 | 담는 것 | 사용자가 할 일 |
|---|---|---|---|
| Claude Code | 플러그인 (GitHub 마켓플레이스 저장소) | MCP 서버 + `/play`·`/stop` 스킬 + 상태 화면 훅 | `claude plugin marketplace add …` → `claude plugin install …` → 세션 다시 열기 → `/play` |
| Claude 데스크톱 | `.mcpb` (GitHub Releases, OS별) | MCP 서버 전체 + 그 OS용 네이티브 모듈 | 파일 더블클릭 → "TRPG 시작해 줘" |
| 그 밖의 에이전트 | npm 패키지 | MCP 서버 | 설정 JSON에 `npx -y <패키지명>` |

- 셋 다 같은 빌드 결과물로 만든다. 플러그인은 엔진을 넣지 않고 npm 패키지를 버전 고정으로 부른다 (`npx -y trpg@<버전>`).
- 사용자 준비물: Claude 구독, Node 22 이상(`.mcpb`는 필요 없음), 디스크 약 1GB(bge-m3 모델).

### 패키지 내용

```
npm 패키지
├─ dist/server.js          core + mcp 번들 (MCP 서버, 상태 화면 서버)
├─ dist/ui/                미리 빌드한 상태 화면 (HTML·JS·CSS, 글꼴)
├─ drizzle/                세이브 DB 마이그레이션
├─ content/scenarios/post_apoc/   기본 월드
└─ package.json            better-sqlite3, sqlite-vec, transformers, MCP SDK

플러그인 저장소
├─ .claude-plugin/plugin.json
├─ .mcp.json               npm 패키지를 버전 고정으로 실행
├─ skills/play, skills/stop
└─ hooks/                  턴 문 훅 (Node 스크립트)

.mcpb
├─ manifest.json           실행 방법, 설정 항목 (RAG 끄기 등)
├─ server/                 npm 패키지 내용
└─ node_modules/           그 OS용 네이티브 모듈
```

- 넣지 않는 것: 테스트, `packages/ui` 소스, Vite, 개발 도구(`war:sim`, `rag:eval`, `eval/`), bge-m3 모델, 사용자 데이터. 치트는 빼거나 꺼 둔다.
- 모더용 검증은 `npx trpg check <팩 폴더>` 같은 하위 명령으로 넣는다.

## 3. 데이터 위치

| 무엇 | 어디 | 업데이트할 때 |
|---|---|---|
| core 엔진, 기본 월드, 상태 화면 | 패키지 안 (읽기 전용) | 원본으로 덮어써짐 |
| 세이브, 해금 기록, 모드, 모델 캐시, RAG 색인 | 사용자 폴더 (`~/.trpg/`) | 그대로 남음 |

- 모두 사용자 PC에 있다. 게임 중 PC 밖으로 나가는 것은 대화와 tool 결과(정보 필터를 거친 Belief State)뿐이고, 받는 곳은 Anthropic(GM)이다. 우리 쪽으로 오는 데이터는 없다.
- 기기 간 동기화는 없다. 백업은 폴더 복사. 파일을 되돌리는 세이브 스컴은 막지 않는다 (1인용).

## 4. 콘텐츠 정책과 모드

- **규칙·판정(core)**: 우리가 관리한다. 모드로 바꿀 수 없다.
- **기본 월드**: 패키지 안에 YAML 팩 파일 그대로 둔다 (**기본안으로 결정**). 번들에 녹이지 않는다.
  - 녹여도 사용자 PC의 텍스트 파일이라 막아 주지 못한다.
  - 모드와 같은 로더를 쓰지 못하게 되고, 모더의 견본이 사라지고, RAG(`lore/` 폴더)와 `content:check`가 복잡해진다.
  - 고쳐도 업데이트하면 원본으로 돌아간다.
- **모드**: 새 월드 팩 추가만 허용한다. 기본 팩과 id가 겹치면 거부한다. 기존 월드에 덧붙이는 모드(overlay)는 지원하지 않는다.
- 로컬 배포라 파일을 직접 고치는 건 기술적으로 막지 않는다. 지원하지 않는 영역으로 둔다.

### 모드를 열 때 필요한 것

- `~/.trpg/mods/` 폴더 읽기 (지금은 `content/scenarios/`만 읽는다, `packages/mcp/src/index.ts`)
- 팩 형식 버전 (스키마가 바뀌면 남이 만든 모드가 깨진다)
- 모더용 검증 명령, 팩 만들기 문서
- **보안**: 모드의 `prompts/`·lore는 GM 프롬프트에 들어간다. Claude Code에서 GM은 터미널을 쓸 수 있으므로, 모드 텍스트를 지시가 아닌 자료로 다루게 GM 지침에 못 박고, "검증되지 않은 모드" 경고를 띄운다.
- 할 수 없는 것: 새 규칙(코드가 필요한 모드). 규칙 플러그인화는 두 번째 장르 때.

## 5. 라이선스와 재배포

- 공개 패키지라 받은 사람이 다시 올리는 건 기술적으로 막을 수 없다. 라이선스로 다룬다.
- 권하는 안: **엔진은 오픈소스(MIT 등), 기본 월드는 재배포·변경 금지(CC BY-NC-ND 등)**. 엔진으로 새 월드를 만드는 건 자유, 가람을 가져다 파는 건 금지.
- 위반은 npm·GitHub 저작권 신고(DMCA)로 대응. 게임 이름 사용 조항도 넣을 수 있다.
- 의존성(MIT 등), bge-m3(MIT), 부산단디명조(공공누리 1유형)는 출처 표시만 지키면 재배포 가능.
- 상업화한다면 최종 문구는 전문가 확인.

## 6. 소개·설치 페이지

- 정적 페이지 하나에 두 겹:
  - **사람용**: 세계관, 플레이 방식, 스크린샷, `.mcpb` 다운로드 버튼
  - **에이전트용 설치 지침** (`install.md` 또는 페이지 안 섹션): Node 버전 확인 → 설치 명령 → 실패 시 대처 → 세션을 다시 열라는 안내 → 첫 실행 때 570MB를 받는다는 안내
- Claude Code 사용자는 주소를 붙여 넣으면 에이전트가 설치까지 한다. 데스크톱 채팅은 명령을 실행하지 못하므로 다운로드 버튼을 쓴다.

## 7. 인프라와 비용

### 로컬 배포 (지금 계획)

- 우리가 돌리는 서버: **0개**
- 페이지는 정적 호스팅, 패키지는 npm, 플러그인·`.mcpb`는 GitHub, 모델은 Hugging Face. 모두 무료 (공개 저장소 전제)
- 선택 비용: 도메인 연 2~3만 원
- 위험: 모델 다운로드가 Hugging Face에 기댄다. 필요하면 GitHub Releases에 사본 (파일당 2GB 제한 확인)

### 원격 MCP (나중에 판단)

엔진·기본 월드·세이브·RAG를 모두 서버에 두고 사용자는 원격 MCP 주소만 등록한다.

- 얻는 것: 코드·월드가 사용자 손에 가지 않음, World State를 진짜로 숨김, claude.ai 웹·모바일 지원, 설치가 주소 등록 하나, 기기 간 이어 하기
- 대가: 서버 운영, OAuth와 사용자별 세이브, 개인정보 처리, 모드는 업로드 방식, 상태 화면은 로그인 붙은 우리 웹, SQLite → Postgres 등
- **엔진만 서버·세이브는 로컬인 반쪽 구조는 하지 않는다.** 엔진은 세이브 전체를 들고 판정하므로 동기화가 복잡하고, 세이브에 World State가 들어 있어 보호도 반쯤만 된다. 모드도 결국 서버로 올려야 한다.

#### 측정값 (2026-11-17, Apple M5, 서버 CPU는 2~3배 느리다고 볼 것)

실제 MCP 서버를 메모리 안에서 띄우고 기본 월드로 90일을 플레이시켰다 (하루에 행동 6, 판정 2, 정보 명령, 장면, 시간대마다 빨리감기). RAG는 끄고 엔진만, 임베딩은 따로 쟀다.

| 항목 | 값 |
|---|---|
| `take_action` | 중앙값 2.9ms, 상위 5% 8.4ms, 최대 36ms |
| `fast_forward` | 중앙값 7.8ms, 상위 5% 24ms, 최대 69ms |
| `get_scene` | 중앙값 1.2ms |
| `start_session` | 113ms |
| 90일 tool 호출 약 1,500번 | 총 8초. 판이 길어져도 느려지지 않음 |
| 열린 세계 하나 메모리 | 막 열면 약 13MB, 오래 하면 수십 MB |
| 서버 프로세스 기본 메모리 | 약 300MB |
| 세이브 크기 (90일) | 약 8MB였으나, 스냅숏 정리(12-110) 뒤 약 2~3MB 예상. gzip으로 약 1/8 |
| bge-m3 로딩 | 1.5초, 메모리 0.9~1.4GB (서버당 한 번) |
| bge-m3 짧은 문장 / 긴 요약(약 340자) | 30ms / 160ms |

- 엔진 CPU는 코어 하나로 동시 접속 수백 명. **한계는 메모리(열린 세계 수)와 임베딩**이다.
- 측정에 없는 것: 실제 GM의 긴 요약과 `recall` 검색. 서버 여러 대로 나누면 같은 서버에 붙이기 또는 Postgres 전환이 필요.

#### 추정 비용 (월)

| 규모 | 동시 접속 | 필요한 자원 | 구성 | 월 비용 |
|---|---|---|---|---|
| 소규모 | ~50명 | 메모리 약 3~4GB | VPS 1대 (4코어·8GB) | 약 2~6만 원 |
| 중규모 | ~200명 | 메모리 약 8~10GB, 코어 2~4 | VPS 1~2대 (8코어·16GB) | 약 7~15만 원 |
| 대규모 | ~1,000명 | 메모리 약 30~40GB, 임베딩 코어 5~10 | 서버 여러 대 + DB | 약 40~80만 원 |

- 저장소: 사용자 1,000명 × 판 3개 = 30GB 안팎, 월 몇천 원
- 로그인: Clerk·Auth0 무료 구간 또는 직접 구현
- 임베딩을 API로 넘기면 서버당 1GB 이상 절약, 사용량 요금은 중규모에서도 월 몇천 원 수준 (모델이 바뀌면 `rag:eval`로 비교부터)
- 가격·무료 구간은 결정 전에 다시 확인할 것

## 8. 상태 화면 (캐릭터 시트)

- 사용자 PC의 `127.0.0.1:8790`에 뜬다 (세션마다 다음 포트). 다른 사람은 볼 수 없다.
- 실시간 갱신은 Vite와 무관하다. 서버가 상태를 확인해 SSE(`/api/status/stream`)로 밀어 주고, 화면은 `EventSource`로 받는다. 정적 파일 서빙으로 바꿔도 그대로 동작한다.
- 여는 방법: Claude Code 데스크톱은 브라우저 패널, 그 밖에는 GM이 알려 주는 주소를 사용자 브라우저로.
- **턴 문(답변이 끝난 뒤 갱신)은 Claude Code 훅이 있어야 한다.** 데스크톱·다른 에이전트에서는 서술보다 시트가 먼저 바뀔 수 있다.
- 글꼴은 CDN이라 오프라인이면 기본 글꼴. 필요하면 글꼴 파일을 패키지에 넣는다.

## 9. 배포 전 작업 순서

1. **데이터 폴더 분리**: `saves/`·`.cache/`를 사용자 폴더로. 지금은 저장소 루트 기준이다 (`packages/mcp/src/index.ts`의 `ROOT`).
2. **빌드**: tsx 대신 JS 번들. drizzle 마이그레이션과 기본 월드 팩을 함께 넣는다. core는 지금 `./src/index.ts`를 그대로 내보낸다.
3. **상태 화면 정적화**: 실행 중에 Vite를 띄우지 않고(`statusServer.ts`), 미리 빌드한 파일을 서빙한다.
4. **첫 실행 다운로드**: 모델은 백그라운드로 받고, 받기 전에는 RAG 없이 돌아가게. 서버 시작이 막히면 클라이언트가 타임아웃을 낼 수 있다.
5. **세이브 마이그레이션**: 형식이 바뀌어도 세이브를 `archive/`로 치우지 않게. 배포 후에는 업데이트마다 판이 사라지면 안 된다. (`MIN_READABLE_SAVE_VERSION`부터는 이벤트를 다시 읽어 올리는 길이 이미 있다)
6. **상태 훅 교체**: `scripts/status-hook.sh`(`sh`·`curl`)를 Node 스크립트로 (Windows).
7. **OS별 확인**: `better-sqlite3`·`sqlite-vec` 네이티브 모듈을 macOS·Windows·Linux에서.
8. **배포물**: npm 패키지, Claude Code 플러그인, 소개·설치 페이지, `.mcpb`, 라이선스(코드·콘텐츠), 사용자용 README.

이미 한 것: 세이브 스냅숏을 마지막 하나만 남긴다 (12-110). 90일 세이브 약 8MB → 약 2~3MB.

## 10. 나중에 정할 것

- 라이선스 (5장의 안으로 갈지)
- 모드 배포 형식 (팩을 파일 하나로 묶을지, 체크섬)
- 기본 팩이 바뀌었으면 "변경됨" 표시를 붙일지 (버그 신고를 가릴 때 쓸모)
- 데스크톱에서 턴 문을 서버 쪽으로 처리할 방법 (예: 다음 tool 호출이나 `record_turn_summary` 때 갱신)
- 오류 보고·사용 통계
- 원격 MCP (웹·모바일 수요가 확인되면)
- 정해지면 기획서 16장의 "배포 형태 결정 (Electron 또는 호스팅 웹)"을 이 문서 내용으로 바꾼다
