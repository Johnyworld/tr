## 4. 판정 시스템: 2d6

### 4.1 기본 규칙

2d6 + 능력 + 스킬 보정 (4.2)

| 결과 | 의미 |
|---|---|
| 10 이상 | 성공 |
| 7~9 | **대가 있는 성공** (성공하지만 무언가를 잃거나, 복잡해지거나, 선택을 강요받음) |
| 6 이하 | 실패 (GM이 상황을 악화시킬 권리를 얻음) |

| 보정치 | 성공 | 대가 있는 성공 | 실패 |
|---|---|---|---|
| -1 | 8% | 33% | 58% |
| +0 | 17% | 42% | 42% |
| +1 | 28% | 44% | 28% |
| +2 | 42% | 42% | 17% |

- 종 모양 분포라 능력치와 준비가 결과에 잘 반영된다
- "대가 있는 성공"이 AI GM이 이야기를 굴리는 핵심 재료
- 판정 함수는 교체 가능하게 만든다 (나중에 분포 조정 가능)
- 보정 = 능력 + 스킬(합쳐서 최대 +4) + 난이도 + 몸 상태 패널티. AI는 스킬·능력·난이도를 enum으로만 고른다
  - 난이도 (*임시*): 쉬움 +1 / 보통 0 / 어려움 -1

#### 4.1.1 상대와 상황 (12-104)

주사위는 주인공만 굴린다 (Apocalypse World 방식을 지킨다: 대가 있는 성공이 한 번의 굴림에서 나오고, 턴이 짧다). 대신 상대의 실력과 상황을 GM이 난이도로 어림하지 않고 코드가 판정 보정으로 바꾸고, 판정 줄에 따로 보인다 (원칙 2, 원칙 6: NPC의 능력·스킬이 판정에 쓰인다).

- **맞서는 상대** (`take_action.check.opponent`, 공격이면 `target`): 상대가 이 스킬에 맞서는 스킬(`opposition.moves`: 은밀 ← 경계, 근접전 ← 근접전, 사격 ← 경계, 경계 ← 은밀, 거짓말 ← 경계, 교섭 ← 교섭, 위협 ← 버티기)의 점수(능력 + 스킬, 상한까지)가 0~1이면 보정 없음, 2~3이면 -1, 4면 -2, 음수면 +1. 판정 줄: `-1(약탈자의 경계)`
- **지켜보는 눈** (`opposition.crowd`): 숨기·속이기는 장면의 사람(동행 빼고)이 3·6을 넘을 때마다 -1
- **어둠·날씨** (`opposition.dark`, `visibility`): 숨기는 밤·새벽 +1(불빛을 켠 사람은 없음), 잘 안 보이는 날씨(visibility 0.7 아래: 안개·비) +1
- **어둠 속 눈** (`opposition.dark.sight`, 공통 규칙 27, 12-366): 어두우면 수색·부대 알아채기 -1, 수색 시간 ×1.5. 손전등(`tool.light`)이 지우되 눈에 띈다. 트레잇 어둠에 익숙함(비용 2: 감점·눈에 띔 없음), 야맹증(+1포인트: -2, ×2)
- **상대의 몫** (`opposition.harm`): 판정이 나빠 주인공이 다칠 때, 상대의 근접전·사격 중 잘하는 점수가 3 이상이면 피해 한 단계 더, 0 이하면 한 단계 덜 (적어도 1단계). 그다음 방어구가 줄인다 (방어구는 맞는 것보다 맞은 뒤에 작용한다). GM에게 "상대의 몫: 약탈자 (근접전 +3) → 솜씨가 좋아 한 단계 더"로 알린다
- **상대가 먼저 움직일 때** (기습, 덤벼듦): 상대가 굴리지 않는다. 주인공이 반응하는 판정(경계, 근접전으로 막기, 버티기)을 하고 그 상대를 `opponent`로 둔다
- GM의 난이도는 그 밖의 상황(지형, 엄폐, 거리, 시간 여유)만 담는다
- 검토한 대안: NPC도 공격·감지 굴림을 따로 하는 방식 (발더스 게이트 3). 결과가 "내가 맞혔나 × 상대가 맞혔나"로 쪼개져 대가 있는 성공의 구조와 부딪히고, 성공해도 다치게 되어 훨씬 위험하며, 라운드마다 굴림과 tool 호출이 늘어 무리 전투를 감당하기 어려워 택하지 않았다
- **상대의 무기** (12-121, `opposition.harm.armed`): 상대가 무거운 피해를 낼 무기(max_harm heavy, 탄약을 쓰면 탄약이 있을 때. 개머리판처럼 탄약 없이 쓰는 스킬이 있으면 그대로)를 들었거나 지녔으면 상대의 몫 +1. 실력과 합쳐 -1 ~ +1로 자른다 (솜씨 좋고 총까지 든 상대도 한 단계 더까지). GM에게 "상대의 몫: 보초 (사격 +1, 엽총) → 엽총을 들었다. 한 단계 더"
- **숨기의 거리** (12-121, `opposition.distance`): 숨거나 몰래 지나갈 때도 상대와의 거리(`check.distance`)를 고른다. 멀면 +1, 맞붙으면 -1, 가까우면 0. 판정 줄에 `+1(먼 거리)`
- 주사위는 숨기지 않는다. 코드가 판정마다 한 줄을 만들고(`🎲 사격: +2(민첩) +2(사격) +1(소총) -1(상한) -1(어려움) +9(주사위) = 12 · 성공`. 스킬·트레잇·동행·무기 보정을 따로 보이고, 상한에 잘린 만큼은 "상한"으로, 0인 보정은 뺀다), GM은 서술 끝에 그대로 옮겨 적는다. 숫자를 GM이 다시 쓰지 않으므로 원칙 2를 지킨다

### 4.2 능력과 스킬 (12-4)

> 예전의 "능력치 5개 + 기본 행동 6개"를 대체했다. 판정의 이름(능력·스킬·범위·상한·성장 수치)은 모두 시나리오 팩 데이터이고, core는 이름을 모른다

**판정**: 2d6 + 능력 + 스킬 + 난이도 + 몸 상태 보정. 결과 구간(10+ / 7~9 / 6-)은 그대로

- **능력 + 스킬은 최대 +4**까지만 더한다 (마스터에 능력 +2여도 +4). 2d6에서 보정 +5부터는 실패가 사라져 긴장이 없어지기 때문이다
- 난이도: 매우 쉬움 +2 / 쉬움 +1 / 보통 0 / 어려움 -1 / 매우 어려움 -2

**능력** (-1 ~ +2): 타고난 것. **계급·역할과 관계없다.** 같은 분대원도 누구는 싸움을, 누구는 머리를 잘 쓴다. 분대장이 멍청할 수도 있다. 바뀌지 않는다

| 능력 | 뜻 |
|---|---|
| 근력 | 힘, 완력 |
| 민첩 | 손발의 빠르기, 정확함 |
| 체력 | 버티는 몸, 지구력 |
| 감각 | 보고 듣고 알아차림 |
| 냉정 | 압박 속의 침착함 |
| 매력 | 사람을 끄는 힘. 판정 밖에서도 작용한다 (아래) |
| 지능 | 배우고 기억하고 따지는 머리 |

- 새 캐릭터 (12-6 캐릭터 생성): 플레이어가 **이름·성별·능력·초상화**를 정한다. 웹은 넷 다 정하고 포인트를 남김없이 써야 시작할 수 있다 (기본값으로 채우지 않는다). 능력은 포인트 구매: 모두 0에서 시작해 4포인트를 나눠 쓴다 (+1은 1, +2는 3, -1로 낮추면 1을 돌려받고 2개까지). 4포인트는 배열 [+2, +1, +1, 0, 0, 0, -1]과 같은 무게다. "무작위"는 코드가 포인트를 배분한다
  - 직업·출신 선택은 보류. 시작 역할(분대원)과 시작 훈련은 역할이 정한다
  - 사망 뒤 "새 캐릭터"로 이어 갈 때도 같은 규칙으로 만든다 (웹: 생성 화면, MCP: `choose_next_character(new)` 뒤 대화로 한 단계씩). 고르지 않고 만들어지는 캐릭터는 배열을 무작위로 섞는다
  - 규칙 수치(포인트, 값별 비용, 낮출 수 있는 수, 성별 목록)는 시나리오 `creation`, 검증은 core(`game/creation.ts`). 웹은 생성 화면, MCP는 아래의 대화식 생성
  - **MCP는 대화로 한 단계씩** (12-13, core `game/creationFlow.ts`): 생성도 이야기의 일부로 느껴지게, GM이 장면처럼 하나씩 묻는다. 새 게임은 그 앞에 월드·시나리오 고르기가 있다 (12.4). 순서: 지금 상황(새 게임만) → 과거 배경 → 이름 → 성별 → 나이 → 능력(포인트 계산 없이 능력 7개 중 가장 자신 있는 것·잘하는 것·자신 없는 것을 한 번에 고른다. 등급과 개수는 `ability_array`에서 나온다) → 스킬 → 트레잇(약점·강점을 한 표에서 번호로 → 성격) → 확인(이대로 시작·한 단계 뒤로·처음부터 다시)
    - **방식 고르기 없음** (2026-11-26): 능력·스킬·트레잇은 늘 직접 고른다. "배경대로 / 고치기 / 운에 맡기기 / 없이"를 묻는 단계는 뺐다. 능력·스킬은 과거 배경의 배치에서 시작해 그대로 넘기면 배경대로(채팅은 "배경대로"), 트레잇은 고르지 않고 넘기면 없이. 운에 맡기기(무작위)는 없다 (고르지 않고 만들어지는 캐릭터의 무작위 배분은 그대로)
    - 뒤로 가도 고른 값은 남는다 (2026-11-26): 답 목록에 위치(`at`)를 두고 뒤로는 위치만 옮긴다. 같은 값을 다시 고르면 뒤의 값을 이어 쓰고, 다르면 버린다. 화면은 남은 값으로 입력·선택을 채운다
    - `start_session(new_world)`·`choose_next_character(new)`가 초안을 열고 첫 단계를 돌려준다. 그 뒤 `create_character(answer | back)`로 한 단계씩. 단계마다 코드가 묻는 것, 보기(클릭 도구용 값과 이름), 남은 포인트·고를 수 있는 값과 트레잇을 계산해 주고 답을 검증한다 (GM은 숫자를 만들지 않는다)
    - 월드 이야기는 `intro`(`prompts/intro.md`), 지금 상황은 시나리오(`roles/*.yaml`의 `scenario.intro`), 단계별 서술 힌트는 `creation.narration` (12.4). 사망 뒤 새 캐릭터는 둘 다 없이 "다른 사람의 삶"으로 운을 띄운다
    - 초안은 MCP 서버 메모리에만 있고, 확인을 마쳐야 세이브가 생긴다. `character`를 한 번에 넘기는 길은 자동 진행·테스트용으로 남긴다
    - 12-11의 브라우저 생성은 12-13에서 뺐다가 12-67에서 **상태 화면 고르기**로 되살렸다 (아래). 12-214부터 채팅으로 만드는 동안에도 상태 화면이 같은 초안을 따라 그린다 (보기만 한다) (11.6 "세 화면")
  - **상태 화면에서 고르기** (12-67): 새 게임(월드 → 시나리오 → 수위 → 캐릭터)과 사망 뒤 새 캐릭터를 상태 화면에서 누르며 고른다. 초안은 채팅과 같은 것(MCP 서버 메모리의 `NewGameDraft`)이고, 화면은 core `newGameView`가 나눠 준 단계를 그린 뒤 고른 것을 채팅과 같은 말로 `answerNewGame`에 넘긴다 (검증·계산은 core)
    - 플레이어가 상태 화면을 고르면 GM은 주소를 알리고 `start_session(new_world, in_browser: true)`(새 캐릭터는 `choose_next_character(new, in_browser: true)`)를 부른다. 이 tool은 플레이어가 "이대로 시작"을 누를 때까지 **기다렸다가** 세계를 열어 돌려주고, GM은 바로 첫 장면을 서술한다. MCP 서버는 세션에 먼저 말을 걸 수 없어서 기다리는 tool 호출이 그 자리를 대신한다 (MCP 표준만 쓰니 다른 MCP 앱에서도 된다). 기다리는 동안 15초마다 진행 알림으로 연결을 잇고, 10분(`TRPG_CREATE_WAIT_MS`)이 넘으면 "다 했어"를 기다렸다가 `create_character(wait: true)`로 이어 가라고 돌려준다 (그 사이 열린 세계는 그 호출이 돌려준다)
    - 화면: 월드 카드(이름·한 줄 소개·짧은 설명, 누르면 바로 고른다. 세계 배경은 튜토리얼 시나리오에서 천천히 익힌다) → 월드 이야기와 시나리오 카드(직접 만들기 먼저, 나머지는 추천 시작) → 수위 → 지금 상황과 이름 → 성별 → 얼굴(12-139: 고른 성별의 얼굴을 화풍 섹션으로 보인다. 고르지 않으면 실루엣. 화면에서 만들 때만 있는 단계라 채팅으로 만들면 없고 실루엣) → 나이 → 능력 방법 → 능력 등급 단추(능력마다 +2/+1/-1, 등급별 개수가 차야 다음) → 트레잇 방법 → 약점·강점 카드(얻은·쓴 포인트, 반대 트레잇은 막는다) → 성격 → 확인. 위에 지금까지 정한 것과 "뒤로"
    - 직접 쓰는 시나리오: 글은 화면에서 쓰고, 옮기기는 GM이 한다. 글을 보내면 기다리던 tool이 돌아가 GM이 `create_character(custom_start)`로 옮기고, 그 뒤 다시 화면 차례가 된다 (화면은 "GM이 옮기는 중")
    - "채팅으로"(도중에 채팅으로 넘기기)는 12-214에서 뺐다: 만들기는 시작한 곳에서 끝까지 한다
    - 다 만들면 상태 화면은 시트로 바뀌고 "Claude 세션에서 첫 장면이 이어진다"를 잠깐 띄운다
    - 상태 서버의 `POST /api/creation`은 Claude 세션이 화면 고르기를 열었을 때만 받는다 (JSON만, 설정 창과 같은 까닭)
  - 초상화는 id만 세이브에 남는다. 월드 팩에 주인공 초상화 목록(`art/portraits.yaml`)이 있으면 그 그림(`art/portraits/<id>.png`, 상태 화면이 `/portraits/<팩>/<id>.png`로 내준다)을, 없으면 코드로 그린 실루엣 12종(`ui/Portrait.tsx`, 예전 세이브도)을 그린다
  - **주인공 초상화** (12-139): NPC 얼굴은 만들지 않고 주인공 얼굴만 고른다. 화풍마다 섹션을 나눌 수 있다. post_apoc은 실사 회화·현대 애니메이션·일본 레트로 일러스트·미국 애니메이션을 시험한 끝에 **미국 애니메이션 하나**(남 28·여 32, 흑백으로 나온 그림은 색을 입혀 차분한 컬러로)로 정했다. 화풍의 `numbered: true`면 얼굴마다 번호를 보인다(번호로 가리키며 다듬을 때). 얼굴을 누르면 바로 고르고 다음 단계로 넘어간다. 화풍이 하나뿐이면 화풍 이름은 보이지 않는다. 얼굴 없이 만든 주인공(채팅으로 만들었거나 고르지 않음)은 시트의 빈 초상화를 눌러 얼굴을 **한 번** 고를 수 있다 ("얼굴을 선택하시겠습니까?" → 예 → 얼굴 목록, 이벤트 `portrait_chosen`, 규칙은 core `game/portrait.ts`, 상태 화면 `POST /api/portrait`). core는 `art/portraits.yaml`에서 화풍 이름(`styles.<id>.label`, 적힌 순서가 섹션 순서)과 얼굴의 화풍·성별(`faces.<id>.style·gender`)만 읽고, 나머지 칸은 그림 생성 도구(`pnpm portraits <팩>`, 로컬 ComfyUI)의 설정이다. 목록이 있는 월드는 목록 밖 id와 다른 성별의 얼굴을 받지 않는다 상태 화면에서도 GM 도구와 같은 규칙으로 장비를 바꾸고 스킬을 올린다 (12-139): 소지품의 무기·방어구를 누르면 들거나 입고, 장비 칸을 누르면 벗을지 묻는다 (`POST /api/equip`, core `GameWorld.equip`, GM의 `equip`). 스킬은 레벨업이 남았으면 + 로 고르고 [저장]을 눌러야 적용한다 (`POST /api/skill`, core `GameWorld.learnSkill`, GM의 `learn_skill`). 결과는 대화 기록에 남아 GM이 다음 장면에서 본다.
  - 그림 생성 (`scripts/portraits.ts`): 화풍마다 모델이 다르다(A·D는 SDXL Base, B·C는 Animagine XL 4.0). 모든 얼굴의 크기·위치를 맞추려고 상반신까지 넉넉히 그린 뒤 얼굴을 찾아(SAM 3.1) 같은 기준(`framing`)으로 자른다. 여백이 많이 모자라거나 원본에 액자·비네트가 있으면 Qwen Image 2.1 편집(`cleanup`)으로 장면을 이어 채우고 지운다. **Qwen Image 2.1은 Qwen RESEARCH LICENSE(비상업, 연구·평가용)라서 배포용 그림에 쓰려면 상업 라이선스를 받아야 한다.** 마음에 든 옛 그림은 `art/sources/`에 두고 `faces.<id>.source`로 그대로 쓴다
  - 캐릭터에 `gender`, `portrait`가 생겼다. NPC도 콘텐츠에 성별이 있다 (GM 상태의 인물 줄에 보인다)
- NPC는 콘텐츠에서 한 사람씩 정한다
- 매력의 수동 효과: 처음 만난 NPC의 호감 시작값 + (매력의 절반, 내림), 호감이 오르는 관계 변화에 매력 +2면 +1. 이성 관계는 3차 범위(연애)에서

**스킬** (-1 할 줄 모름 / 0 아마추어 / +1 숙련 / +2 마스터): 배우는 것. 역할이 시작 훈련을 준다 (분대원은 근접전·사격). 스킬마다 쓸 수 있는 능력이 정해져 있고, GM은 그중 상황에 맞는 하나를 고른다. 스킬마다 기본값(배우지 않았을 때)이 있다

- 시나리오 팩 데이터: 능력·스킬 목록, 스킬별 능력·기본값, 범위, 상한. core는 이름을 모른다

**경험치와 성장**

- 경험치: 판정 성공 +1, 대가 있는 성공 +1, **실패 +2** (실패에서 배운다), 공적 1당 +2. 판정 경험치는 하루 최대 6 (사소한 판정을 쌓아 올리는 것을 막는다)
- 레벨은 1부터 시작한다. 레벨업 (12-109): 경험치 5(레벨 2)에서 시작해 레벨마다 ×1.3 (`growth.first`·`step`·`ratio`). **최대 레벨 20** (`growth.max_level`: 하루 경험치가 5~8이라 레벨 10에 한 달, 15에 넉 달, 20에 1년이 넘게 걸린다). 레벨업마다 **스킬 하나 +1** (최대 +2). 능력은 오르지 않는다
- **버팀** (12-109, `growth.resilience`, 구간 목록): 레벨 1은 0%, 레벨업마다 레벨 2~5는 4%, 6~10은 3%, 11~15는 2%, 16~20은 1% (레벨 5에 16%, 10에 31%, 15에 41%, 20에 46%). 몸이든 마음이든 상태 트랙이 한 단계 나빠질 때(판정 피해, 사망 단계 포함) 그 확률로 그 단계를 피한다. 발끈·말 새어 나감에는 쓰지 않고, 치트에도 쓰지 않는다. 피한 변화가 보이는 것이면 "버텨 냈다"고 알린다. `engine/growth.ts` `resistSteps`, `body.ts` `changeCondition`, `action.ts` `applyHarm`
- 고르는 것은 플레이어다. 쌓인 레벨업은 상태와 `!상태`에 보이고, GM이 플레이어에게 물어 `learn_skill(skill)`로 올린다
- 다음 캐릭터로 이어 가면 경험치·레벨은 그 캐릭터의 것이다 (NPC로 이어 가면 그 인물의 스킬)

#### 4.2.1 스킬 개편: 누구나 하는 일과 전문 기술 (2026-11-20, 구현 12-208)

> 플레이 테스트 11에서 GM이 굴린 판정을 행동별로 다시 보니, 스킬 몇 개가 서로 다른 일을 떠안았다 (버티기로 오르기·들기·나르기, 생존으로 낚시·사냥·개 훈련·헤엄, 교섭으로 캐묻기·속마음 읽기·다툼 중재). 동시에 응급처치·차량정비처럼 배워야 하는 일을 누구나 -1로 굴렸다. 아포칼립스 월드처럼 능력이 판정의 중심이고, 스킬은 "그 일을 할 줄 아는가"와 "얼마나 익혔는가"를 정하게 바꾼다

**판정은 그대로**: 2d6 + 능력 + 스킬 + 난이도 + 몸 상태. 능력 + 스킬 상한 +4도 그대로 (능력 +2와 마스터 +2가 만나면 +4)

**스킬은 두 갈래다** (스킬마다 `kind`를 둔다. 시나리오 팩 데이터)

| 단계 | 값 | 누구나 하는 일 (`common`) | 전문 기술 (`expert`) |
|---|---|---|---|
| 못 함 | — | 없다 | 배우기 전. 판정할 수 없다 (도구가 거절하고, 배운 사람을 찾으라고 안내한다) |
| 미숙 / 배움 | -1 | 찍지 않은 상태 (처음부터) | 배운 직후. 이제 판정할 수 있다 |
| 할 수 있음 | 0 | 스킬 포인트로 올린다 | 스킬 포인트로 올린다 |
| 숙련 | +1 | 스킬 포인트로 올린다 | 스킬 포인트로 올린다 |
| 마스터 | +2 | 스킬 포인트로 올린다 | 스킬 포인트로 올린다 |

- 누구나 하는 일은 찍지 않아도 굴릴 수 있다. 다만 미숙한 상태라 -1이다 (2026-11-20 정함: 0이 아니라 -1). 거짓말, 겁주기, 몸 숨기기는 배우지 않아도 할 수 있지만 서툴다
- **시작 스킬 포인트 12점** (2026-11-20 정함): 스킬은 과거 배경(붕괴 전 직업, `creation.pasts`)에서만 받는다. 과거를 고르면 **12점을 다 쓴 기본 배치**가 따라오고, 플레이어는 같은 12점 안에서 고쳐 쓸 수 있다. 전문 기술은 과거가 가르쳐 준 것으로 보고 배운 상태(-1)에서 점수를 센다. 쓰지 않은 점수는 남겨 레벨업 점수와 함께 쓴다
- **계급 기본 훈련(`creation.rank_skills`)은 없앤다.** 계급이 꼭 요구하는 **전문 기술**(분대장의 전략)만 점수 없이 "배운 상태(-1)"로 준다. 잘하려면 플레이어가 점수를 쓴다. 누구나 하는 일(간부의 교섭)은 따로 주지 않는다
- **직분(`occupations`)은 남기되 스킬은 주지 않는다** (일감·평판·도구는 그대로). 직분의 스킬이 전문 기술이면(의무병의 응급처치, 목수의 목공, 정비공의 차량정비) 계급과 같이 "배운 상태(-1)"로만 준다 (직분에 맞춘 배치는 두지 않는다, 아래)
- **과거 배경의 12점 배치**: +2 하나(6점), +1 하나(3점), 0 셋(1점씩)

| 과거 | +2 | +1 | 0 |
|---|---|---|---|
| 소방관 | 버티기 | 운동 | 응급처치, 경계, 근접전 |
| 경찰 | 사격 | 눈치 | 경계, 위협, 근접전 |
| 군인 | 사격 | 전략 | 근접전, 운동, 경계 |

| 도둑 | 은밀 | 거짓말 | 수색, 운동, 눈치 |
| 조폭 | 위협 | 근접전 | 버티기, 거짓말, 운동 |

| 학생 | 수색 | 급조 | 수영, 역사, 은밀 |

- **직분에 맞춘 배치는 두지 않는다** (2026-11-20 정함): 경찰 출신이 의무병을 맡았다고 응급처치를 잘할 리 없다. 직분의 전문 기술은 배운 상태(-1)로만 주고, 잘하려면 점수를 쓴다
- 캐릭터 만들기의 스킬 단계: 능력 다음, 과거를 고른 뒤 위의 배치를 보여 준다 (채팅·상태 화면 모두)
- 전문 기술은 **배워야** 시작할 수 있다. 배우면 -1이 되고, 그때부터 레벨업 포인트로 올릴 수 있다. 수술, 차량정비, 목공, 수영처럼 모르면 손댈 수 없는 일이다
- NPC도 같은 규칙이다 (원칙 6). 콘텐츠에 적지 않은 누구나 하는 일은 -1, 전문 기술은 "못 함"이다. NPC·엑스트라 콘텐츠의 스킬을 다시 맞춘다 (지금은 적지 않으면 0인 것이 많다). 맞서는 판정에서 상대가 그 스킬을 못 하면 상대 보정은 +1(서툰 상대와 같다)

**스킬 포인트**: 레벨업마다 1점. 올리는 값은 단계마다 다르다

| 올리기 | 필요한 점수 |
|---|---|
| -1 → 0 | 1 |
| 0 → +1 | 2 |
| +1 → +2 | 3 |

- 누구나 하는 일을 마스터까지: 1 + 2 + 3 = 6점. 전문 기술을 배움에서 마스터까지도 6점 (배우는 것은 점수가 아니라 가르침으로)
- 점수는 모아 둘 수 있다 (지금처럼 쌓인 레벨업을 플레이어가 고른다. `learn_skill`과 상태 화면의 +). 모자라면 + 단추가 막힌다

**전문 기술을 배우는 길** (판정이 아니라 자격을 얻는 일)

1. 시작: 역할·직분·과거가 주는 스킬 (지금의 시작 스킬). 계급·직분의 전문 기술은 배운 상태(-1), 과거가 준 것은 배치대로
2. 가르침: 그 스킬이 +1 이상인 사람에게 배운다. 그 사람의 신뢰 1 이상, 곁에서 "배우기" 활동을 모두 8시간(여러 번에 나눠도 된다) 채우면 -1이 된다. 가르치는 사람이 같은 무리면 쉽게 응하고, 다른 무리면 물건으로 값 5를 받는다 (치료사의 값과 같은 틀, 가르치는 사람의 신뢰 2 이상이면 공짜). 배우는 동안의 시간은 코드가 센다 (GM은 숫자를 만들지 않는다)
3. 책·교본(나중): 그 스킬의 책이 있으면 혼자 배운다 (시간 두 배). 이번 개편에는 넣지 않는다

**스킬 목록** (분류는 제안. 결정 칸이 빈 것은 정해야 한다)

| 트랙 | 단계 (판정 보정) | 나빠지는 원인 | 나아지는 길 |
|---|---|---|---|
| 추위 | 따뜻함 0 → 쌀쌀함 0 → 추위 -1 → 저체온 -2 | 하루마다 계절·날씨의 추위(겨울, 눈, 한파, 비에 젖음)만큼. 우리 거점에서 무리의 연료가 있으면 막아 준다. 밖에서 밤을 나면 더 춥다 | 연료가 있는 거점에서 하루를 나면, 방한 물건(담요·방한복)을 쓰면, 불을 피우면(생존 판정) |
| 질병 | 없음 0 → 잠복(숨김) 0 → 앓음 -1 → 위중 -2 | 하루마다 확률. 굶주림 이상·추위 이상·무리의 물 부족(더러운 물)·북적이는 거점에서 높아진다. **체력**이 높으면 덜 걸린다 | 약(항생제 등), 치료사, 따뜻하고 배부르게 쉬면 하루마다 확률로 낫는다 (체력이 높을수록 잘 낫는다) |

- 질병의 잠복은 감염처럼 캐릭터도 GM도 모른다. 앓기 시작하는 날 알게 된다
- 감염(감염체에게서)과 질병(몸이 약해져서)은 따로다. 감염은 상처에서, 질병은 생활에서 온다
- 체력은 질병에 걸리고 낫는 확률에, 버티기 스킬은 추위·고통 속 판정에 쓴다
- 수치(계절·날씨별 추위, 확률, 배수)는 시나리오 팩 `body.cold`, `body.disease` (*임시*): 겨울 1, 눈·비 1, 한파 2, 방한복 -1, 연료 하루치 이상인 우리 거점에서 2단계 녹음. 질병 하루 1% + 굶주림 5% + 추위 5% + 무리의 물 부족 6%, 체력 1당 25% 덜, 배부르고 따뜻하면 하루 35%(+체력 1당 10%)로 낫고 아니면 30%로 깊어짐
- 새 아이템: 담요(쓰면 추위 2단계), 방한복(들고 있으면 추위 1 덜), 해열제(질병 1단계). 치료사는 질병도 1단계 낫게 한다
- (12-98) 하루 단위 추위는 기온(4.5.2)으로 바뀌었다. 위의 하루 단위 규칙은 `body.cold.climate`가 없는 월드에만 남는다. 담요는 덮는 물건, 방한복은 외투 칸에 입는 것이 됐다
- 불 피우기(생존 판정)로 몸을 녹이는 것은 아직 없다. 지금은 거점의 연료·담요·방한복으로만 막는다

### 4.4 부상 (*초안*)

상태 트랙의 이름·단계·보정은 시나리오 팩이 정한다. 사망은 `harm_track`의 마지막(fatal) 단계로만 일어난다

- 부상 트랙: 무사 → 경상 → 중상 → 치명상 → 사망
- 부상 패널티 (*임시*): 경상 -1 / 중상 -2 / 치명상 -3
- 피해는 반드시 **판정 하나**에 묶이고, 위험은 **판정 전에** 선언한다 (`take_action`의 `check.harm_on_failure`)
  - 대가 있는 성공: 1단계 악화
  - 실패: 선언한 위험에 따라 가벼운 피해 1단계, 심각한 피해 2단계 (*임시*)
  - 성공했거나 위험을 선언하지 않았으면 다치지 않는다
- 부상은 며칠간 행동 패널티로 남는다. 한 번의 실수가 연쇄로 이어지게
- **회복** (12단계, 수치는 시나리오 `recovery`, *임시*)
  - 치료: 장면에 있는 치료사(NPC `healer`)에게 받거나(`take_action.treatment`, 하루 한 번이지만 그 뒤 더 다치면 다시 받는다, 부상 1단계. 감염은 혈청뿐, 12-106. 치료사의 치료와 주인공이 하는 응급처치·간호는 칸이 따로다, 12-236), 소모품을 쓴다(`take_action.use_item`, 4.5). 낫는 정도는 코드가 정한다
  - 저절로: 새 부상 없이 이틀이 지나면 한 단계. 중상까지만 저절로 낫고, 치명상은 치료가 필요하다
- **의식불명** (증상의 `incapacitates`): 스스로 아무것도 하지 못한다. 판정·이동·물건 쓰기·대화성 tool(이야기 고르기, 흥정, 장비, 지휘 등)이 막히고, take_action은 시간 흐르기(wait·sleep, 전투 중이면 활동 없이)와 장면의 치료사에게 돌봄 받기만 된다. 이야기는 열리지 않고, 진행 중이던 이야기는 의식을 잃으면 닫힌다. GM 장면에 "흐릿한 감각의 조각만 서술한다"가 붙는다. 그 단계에 `recovery.wake_hours`(6시간, *임시*) 머물면 정신이 든다 (의식장애로 한 단계)
- **상처 종류와 출혈** (12-91, `wounds`): 몸의 위험을 걸면 GM이 상처 종류(`check.harm_kind`: 베임·찔림·총상·물림·할큄·둔기·그 밖)를 고른다. 피가 나는 종류로 다치면 부상 단계에 맞춰 출혈 트랙이 오른다 (경상 → 긁힘, 중상 → 출혈, 치명상 이상 → 심한 출혈). 출혈은 판정 보정이 없고 피가 나는지만 알린다. 출혈은 6시간, 심한 출혈은 1시간마다 부상을 한 단계 키우고, 긁힘은 한 시간이면 멎는다. 출혈 이상이면 정신이 들지 않고 저절로 낫지 않는다. 지혈: 붕대·구급상자(멎음), 치료사, 맨손(응급처치 판정: 성공 멎음, 대가 있는 성공 한 단계), 곁의 사람의 돌봄, 붙잡은 쪽도 상처를 묶는다. 피를 흘려 부상이 깊어지면 출혈도 그 부상 단계만큼 심해진다. NPC도 같은 규칙으로 흘린다 (원칙 6): 주인공이 친 상처의 종류는 무기·맨손 데이터(`weapon.wound`, `gear.unarmed.wound`: 스킬별, 소총은 쏘면 총상·개머리판은 둔기)에서 오고, 장면에 있는 사람은 흘린 만큼 깊어지며(주인공이 붕대·응급처치·맨손 지혈 판정으로 멎게 할 수 있다), 장면 밖의 무리 사람·포로는 곁의 사람이 지혈하고, 무리 없는 사람은 계속 흘린다. 피가 멎지 않으면 NPC도 저절로 낫지 않는다. 상처 종류에 물림(`bite`)과 할큄(`claw`)을 나눴다 (12-106). 감염체에게 다칠 위험(`infected_source`)이면 상처 종류를 비워도 할큄(`wounds.infected_default`)으로 보고, 감염은 피가 나는 상처일 때만 굴린다 (덮쳐 넘어뜨린 둔기 상처로는 감염되지 않는다). 값은 *임시*
- **의식불명 중 곁의 사람** (12-90, `helpless`): 쓰러질 때마다 한 번, 곁에 누가 있느냐로 코드가 정한다 (GM이 서술로 정하지 않는다). 적(무리 태도 `hostile_disposition` 이하, 그 사람의 믿음+호감 `hostile_regard` 이하, 떠돌이면 `prey_on_strangers` 무리)이 우리 편보다 많거나 같으면 끌고 가 가두고(포로 규칙), 확률(`kill`: 기본 + 자비 가치관 + 원한)로 죽인다. 우리 편(동행, 같은 무리, 우호 무리, 믿음+호감 `ally_regard` 이상)이 있으면 돌봐 한 단계 낫게 하고(정신이 든다), 동행이 아닌 무리 사람이면 그 무리 거점으로 옮긴다. 장면에 아무도 없으면 구역 주인 무리가 `found_chance`로 찾아내고(우리 편이면 돌봄, 적이면 붙잡음), 아무도 찾지 않으면 구역의 감염체 압력(7.5.2)별 `infected_chance`로 감염체에게 물린다 (곁에 감염체가 있으면 반드시, 7.5.1). 결과는 주인공의 기억과 take_action 결과 문장으로 GM에게 간다. 무리 전투 중에 쓰러지면 남은 전투를 코드가 한 번에 굴려 끝내고(물러났을 때처럼), 이겼으면 우리 무리가 돌보고(옮김), 졌으면 적의 손에 떨어진다(같은 죽임·붙잡힘 확률). 포로 규칙의 `on_defeat`에도 의식장애·의식불명 단계를 둔다(helpless 규칙이 없는 월드용). 값은 *임시*
  - 플레이 테스트 1회차 문제 4("치료받았는데 그대로")와, 회복이 없어 랜덤 자동 플레이에서 70일에 20~30번 죽던 문제를 고쳤다
- 감염은 별도 트랙 (4.5)
- **수술** (12-159, `recovery.surgery`): 부상이 치명상 이상인 사람을 돌보는 것은 판정이다
  - 치료사(NPC)에게 받으면 코드가 굴린다: 2d6 + 지능 + 응급처치(상한 안) + 장소 (하얀매 진료소 +1, 거점 0, 거점 밖 -1, *임시*). 결과 줄에 🩺 굴림이 보인다
  - 주인공이 남을 돌보면 응급처치 판정(`check`)을 걸어야 한다. 구급상자 같은 도구는 판정의 도구 보정으로 들어간다
  - 성공 = 한 단계 낫는다, 대가 있는 성공 = 낫되 흔적(4.4.1)을 굴린다, 실패 = 한 단계 나빠진다 (하루 한 번은 그대로)
  - 피가 나고 있으면 먼저 지혈한다 (같은 응급처치 판정이 지혈로 간다)
  - 소모품(구급상자를 써서 부상 한 단계)은 그대로다. 혼자서 하는 수술은 다루지 않는다

#### 4.4.1 몸에 남는 상처 (12-156)

크게 다친 몸은 다 나아도 예전 같지 않다. 오래 가는 약점을 트레잇(4.6) 하나로 다룬다. 새 규칙 없이 트레잇 효과를 그대로 쓴다.

- **언제**: 부상이 `scars.at`(치명상) 이상이 되는 상처를 입을 때마다 `chance`(30%)로 굴린다. 주인공이 판정 실패로 다칠 때와, 주인공이 NPC를 칠 때 모두 (원칙 6)
- **무엇**: `scars.traits`에서 그 상처 종류(`wounds`)에 맞는 것 중 아직 없는 것 하나. `wounds`가 비면 어느 상처로든. 한 사람에 `max`(3)개까지
- **고를 수 없다** (`selectable: false`). 캐릭터 생성에는 나오지 않는다. 고칠 길도 없다
- `post_apoc` (*임시*): 절뚝임(은밀 -1, 총상·찔림·물림·둔기·베임), 굳은 손(사격 -1, 베임·물림·할큄·총상), 얼굴 흉터(외모 -1·위협 +1, 겉으로 보인다, 베임·할큄·그 밖), 짧은 숨(버티기 -1, 총상·찔림·둔기), 먹은 귀(경계 -1, 둔기·총상·그 밖), 쑤시는 옛 상처(추위 노출 +1, 어느 상처로든)
- 결과 줄: "이 상처는 아물어도 흔적을 남길 것이다: 절뚝임 (...)". GM은 다친 장면에서 흔적을 서술하고, 그 뒤로는 트레잇의 연기 지침대로 그린다
- 이벤트는 `character_patched`(트레잇). 세이브 형식은 그대로

### 4.5 몸 상태: 허기와 감염 (12-1). 추위와 질병은 4.2 (12-4)

상태 트랙이 셋이 됐다: 부상, 허기, 감염. 이름·단계·보정은 시나리오 팩, 규칙은 core(`engine/body.ts`). (12-74부터: 허기·추위·감염은 부상을 주지 않고 그 트랙의 끝 단계에서 죽는다. 사망은 여전히 코드가 상태 트랙으로만 정한다, 원칙 3)

- **허기** (든든함 → 허기짐 → 굶주림 -1 → 기진함 -2): 하루가 지날 때 소속 무리의 배급 수준만큼 바뀐다 (`war.ration.levels[].hunger`, `hunger_max`)
  - 정량: 2단계 나아진다 / 줄어든 배급: 허기짐까지만 / 반쪽 배급: 굶주림까지만 / 배급 끊김: 끝까지. 기진함이면 하루마다 굶주림으로 부상 1단계
  - 전쟁·계절이 무리의 식량을 바꾸고, 그게 배급을 거쳐 캐릭터의 몸에 닿는다 (9.3 "배급")
  - 통조림(`use_item`)으로 2단계 나아진다
- **갈증** (12-97, 괜찮음 → 목마름 → 탈수 -1 → 심한 탈수 -2·의식장애 → 의식불명 → 죽음): 하루마다 한 단계 마른다 (`body.thirst.daily`). 허기보다 빨리 죽는다. **저절로 마시지 않는다**: 플레이어가 직접 마시고 채운다
  - 바깥의 물이 나는 구역(산출에 물: 강변·정수장 등): `take_action.drink`로 3단계 풀림, `refill`로 빈 물병을 채운다 (따로따로)
  - 우리 거점: 물 보급. `refill`이면 채우면서 마시기까지 한다 (`drink`는 마시기만). 무리의 물이 하루치 이상이면 넉넉히, 그보다 적으면 한 모금(1단계)·물병 하나만, 바닥이거나 배급 권한이 없으면 거절. 창고 사정은 GM에게 미리 알리지 않는다
  - GM 상태의 "물" 줄: 목이 마르거나 빈 물병이 있을 때만 보인다. 바깥이면 "물이 충분하다(빈 물병이 있으면 채우면 될 것 같다)", 거점이면 창고 사정과 상관없이 "물 보급을 받아야 할 것 같다"를 서술에 한 번 언급한다
  - 물병 2단계(마시면 빈 물병이 남는다, 아이템 `used_into`), 오이·토마토·사과 1단계. 말린 생선·절임 고기는 짜서 1단계 마르게 한다 (`consumables`의 음수). 갇혀 있으면 목마름까지만
  - 탈수부터 질병 확률이 오른다 (`disease.chance.thirst`, 갈증 규칙이 있으면 무리의 물 부족 대신)
  - 시뮬레이션(19역할 × 250턴): 처음(밖에서만 마르고 우리 땅은 저절로) 9명 목말라 죽음 → 직접 마시기·채우기와 탈수면 거점으로 돌아가기를 넣은 뒤 0명. 탈수 이상 2%. 얼어 죽음 2명은 갈증을 끈 판에서도 2명이라 갈증과 무관
- **감염** (없음 → 잠복 이틀(숨김) → 몸살 기운(12-193 전 추움) → 오한 → 깊은 오한 → 고열 → 깊은 고열 → 위중 → 변이, 물리고 변이까지 여드레, 12-109): 
  - GM이 위험을 선언할 때 감염체에게서 오는 위험이면 `check.infected_source: true`. 그 판정으로 다치면 코드가 **상처 종류별 확률**(`body.infection.chance`: 할큄 20%, 베임·찔림 35%, 물림 60%, *임시*)로 잠복기를 만든다 (12-106). 위험의 크기(경상·중상)는 피해에만 쓰고 감염 확률에는 쓰지 않는다. 쓰러진 사이 물리면 가장 위험한 종류로 본다
  - **잠복기는 숨은 단계**(`hidden`)다. 캐릭터도 GM도 모른다. 상태·명령어·화면에는 "없음"으로 보인다
  - 하루마다 한 단계씩 나빠진다. 발열이 되는 날 GM에게 "감염: 없음 → 발열"로 알린다. 악화면 하루마다 부상 1단계
  - **한 번 걸리면 혈청 없이는 낫지 않는다** (12-106). 치료사·무리의 돌봄·소모품은 감염을 떼지 못한다 (혈청이 있는 월드면 `recovery.healer`·`consumables`에 감염 트랙을 적으면 검증 오류)
  - 늦추는 약(`body.infection.slow`, 항생제): 하나 먹으면 하루 동안 듣고, 그동안은 하루 멈추고 하루 퍼진다 (확정형 절반 속도). 계속 먹으면 변이까지 여드레 → 보름쯤. 상태 `recovery.slowDay`·`heldDay`(날 단위), 이벤트 `infection_slowed`·`infection_held`. NPC도 같다
  - 떼는 약(`body.infection.cure`, 혈청): 감염을 처음 단계로 되돌린다. **잠복에도 듣고, 걸렸는지 몰라도 쓸 수 있다** (안 걸렸으면 버린 셈. 쓸 수 있느냐로 잠복이 새지 않게)
  - 혈청 구하기: 떠돌이 약장수·나루상단 상인이 떨어졌을 때 하루 한 번 낮은 확률로 들여오고(상인 `merchant.rare`), 하얀매 진료소 간호사가 하나 지니며, 진료소·옛 시립병원 수색과 길 위 사람들의 짐(시체)에서 드물게 나온다. 값 60. 항생제는 재고를 늘렸다
- **소모품** (`consumables`): 아이템 → 트랙 → 나아지는 단계. 구급상자 부상 1, 항생제 부상 1, 통조림 허기 2. 나아질 데가 없으면 쓰지 않는다
- 하루가 지나며 바뀐 몸 상태는 `take_action` 결과 문구로 GM에게 알린다
- 이전 세이브: 새 트랙이 없는 캐릭터는 그 트랙의 첫 단계로 읽는다
- 대규모 전투는 개인 판정과 별도 규칙(병력·사기 중심)으로 처리

#### 4.5.1 공포 (12-95)

좀보이드의 패닉처럼 **그 자리에서 확 올랐다가 몇 시간 안에 빠지는 단기 상태**. 마음(`nerves`, 며칠에 걸쳐 쌓이고 가라앉는 상처)과 따로 둔다. 공포로 죽지는 않고 판정만 어려워진다. 규칙은 core `engine/fear.ts`, 수치는 `body.fear`. 주인공만 계산한다

- **트랙 `fear`**: 평정 → 긴장 → 겁먹음 → 공황. 증상 묶음 `fear` (긴장 0, 겁먹음 -1, 공황 -2, *임시*). 증상이라 상태 화면과 판정 줄에 그대로 보인다 (`-2(공황)`)
- **공황의 효과는 판정 보정뿐**. 행동을 막거나 플레이어 대신 도망치게 하지 않는다 (원칙 5: 의도는 플레이어의 것). GM은 떨리는 손, 좁아지는 시야로 연출한다
- **오르는 계기** (오를지·얼마나는 코드가 정한다, 원칙 2). 한 tool에서 여럿이 일어나면 가장 큰 것 하나로 센다
  - 데이터: 이야기의 `fright: 1~3`(열릴 때), 엑스트라 틀의 `fearsome: 1~3`(장면에 새로 나타날 때, 셋 이상이면 +1), 무리 전투가 붙을 때(`battle`). tool 전후의 장면을 비교해 core `executeTool`이 붙인다. 감염체 무리·떼·밤길·지하 터널·매복 이야기 16개에 `fright`를 붙였다. 감염체 엑스트라 틀은 아직 없다
  - GM enum: 데이터로 잡히지 않는 순간이면 `take_action.fright: none | startle | dread` (`gm`: startle +1, dread +2). 판정보다 먼저 적용해 그 턴의 판정에 바로 붙는다
  - 곁의 사람(장면·동행)이 눈앞에서 죽으면 마음과 함께 공포도 `witness_death` (감염체의 죽음은 빼고)
- **더하고 빼기**: 어둠(`dark.segments`, 밤) +1, 동행이 곁에 있으면 -1, 트레잇 효과 `fear`(겁쟁이 +1, 강철 신경 -1), 마음이 `nerves_from`(미칠 것 같음) 이상이면 +1, 그다음 주인공이 **마음 다잡기**(`body.steady`: 버티기 + 냉정, 12-220)를 굴린다. 성공이면 오르지 않고 GM에게 "눌러 참았다"고 알리고, 대가 있는 성공이면 한 단계 덜(적어도 한 단계), 실패면 그대로. 이미 공황이면 굴리지 않는다
- **둔감해짐은 뺐다** (12-185): 겪을 때마다 노출을 세어 문턱(10·30)을 넘으면 덜 오르던 규칙. 따로 세는 상태가 필요한데 플레이에서 보이지 않았다. 예전 세이브의 `fear_exposed`는 읽기만 하고 무시한다
- **가라앉기**: 공포를 부른 것(전투, `fright`가 있는 진행 중인 이야기, `fearsome` 인물)이 장면에 없으면 마지막으로 바뀐 때부터 `decay_hours`(1시간)마다 한 단계. 자고 나면 평정
- **마음과 이어짐**: 마음 다잡기가 실패해 공황에 이르면 마음 트랙 +1 (다시 굴리지 않는다, 12-220)
- **아는 것은 덜 무섭다는 뺐다** (12-185): 감염체 지식이 감염체 공포를 한 단계 덜던 규칙(`body.fear.lore`)과 공포 태그 `infected`. 같은 스킬이 하는 일을 하나 더 얹을 뿐이었다
- **공포증** (12-103): 약점 트레잇의 효과 `phobia: [태그]`. 계기의 태그(이야기·엑스트라의 `fright_tags`, GM이 즉흥 장면에 고르는 `take_action.fright_tags`)에 그것이 있으면 한 단계 더 오르고, **보통 사람에게 무섭지 않은 장면(fright 0)에도 온다**. `dark`는 어둠 시간대 전부. 값 (12-108): 자주 터지는 어둠·폐소는 2, 드문 물·개는 1이고, 공포증은 하나까지(`creation.traits.max_phobia`). 콘텐츠의 태그 수는 폐소 17곳, 물·개 5곳, 어둠 3곳 + 밤의 모든 공포라, 드문 공포증을 쌓으면 거의 공짜 포인트였다. 트레잇의 `acting`으로 GM이 연기한다 (숫자와 연기를 함께 가진 트레잇)
  - 어둠 공포(`dark`), 폐소 공포(`enclosed`: 지하·터널 17곳), 물 공포(`water`: 잠긴 곳 5곳), 개 공포(`dog`: 개 이야기 3개, 엑스트라 2종). 비용 1, *임시*
  - 태그는 목록이라 한 장면에 여럿 붙는다 (지하 터널의 감염체 = infected + enclosed + dark). 한 tool에서 계기가 여럿이면 단계는 가장 큰 것 하나, 태그는 모두 본다
- **다음 단계**: NPC의 공포가 무리 전투 사기·도주에 미치는 것. 감염체 엑스트라 틀과 `fearsome`은 12-111에서 넣었다 (7.5.1)

#### 4.5.2 기온 (12-98)

하루에 한 번 "오늘 얼마나 추운가"를 단계로 따지던 추위를, **시간대마다 기온을 재고 그동안 있던 곳의 체감 기온으로 냉기를 쌓는** 방식으로 바꿨다. 규칙은 core `engine/climate.ts`, 수치는 `body.cold.climate` (*임시*). 기온은 코드가 정하고 GM은 결과의 숫자로 서술만 한다 (원칙 2). 주인공만 계산한다

- **바깥 기온** = 계절 평균(겨울 -3°, 봄 9°, 여름 24°, 가을 8°) + 시간대(새벽 -5, 아침 -2, 낮 +3, 저녁 0, 밤 -4) + 날씨(안개 -1, 비 -2, 눈 -3, 한파 -10) + 그날의 들쭉날쭉 ±2 (세계의 씨앗과 날에서 정해져 같은 날은 늘 같다. 씨앗은 세계를 만들 때 세계의 RNG에서 뽑는다(`worldSeed`, 12-113). 예전에는 시각이 든 세계 id로 정해 같은 시드의 자동 플레이도 판마다 달라졌다). 겨울 맑은 날은 새벽 -8°·낮 0°·밤 -7°, 한파는 새벽 -18°
- **어디에 있는가는 자동으로** 정한다: 이동·수색·보초·전투는 바깥, 나머지 활동(잠·휴식·대화·식사·작업·기다림)은 그 구역의 실내. 구역마다 실내가 바깥보다 따뜻한 도 `cover` (거점 6~7, 온전한 건물 5~6, 폐허 4, 초소·밭 2~3, 무너진 고가도로 0). cover 0이면 쉬어도 노숙이다. 실내는 날씨를 절반만 받는다
- **체감 기온** = 바깥 + 실내 + 모닥불 +10 + 방한복 +4(입었을 때, 12-186에 +6에서 낮춤) + 담요 +5(지니고 자거나 쉴 때) ∓ 체질(추위를 탐 -3, 추위에 강함 +3). 불 땐 거처(우리 거점, 무리 연료 하루치 이상)의 실내는 16° 아래로 내려가지 않는다
- **냉기**: 체감이 8°보다 낮으면 (모자란 도 × 시간)만큼 쌓이고 100마다 추위 한 단계. 8° 이상이면 시간당 20, 15° 이상이면 50씩 빠지고 100마다 한 단계 풀린다. 멀쩡할 때는 따뜻함을 쌓아 두지 않는다. 캐릭터마다 `coldLoad` (세이브 형식 40)
- **모닥불**: `take_action.use_item`에 연료(땔감 8시간(12-186, 하룻밤), 나무 판자 3시간, 기름 한 병 2시간). 그 구역에 있으면 체감 +10, 피우면 그 구역 소음 +1 (연기와 불빛). 상태 `fires` (구역 → 꺼지는 시각). 땔감은 구역 10곳의 뒤지기 표에
- **옷차림**: 아이템 `warmth { degrees, when: worn | resting }`. 방한복은 새 장비 칸 **외투**(`outer`)에 입는다 (몸 칸 방어구 위에 따로. 두꺼운 솜이 물림을 30% 막는다). 가지고 시작하면 저절로 입는다. 담요는 소모품이 아니라 덮는 물건이다
- **보이는 곳**: GM 상태의 "기온" 줄(바깥 기온, 여기서 쉬면 체감과 내역, 모닥불이 몇 시간 남았는지. 불 피우기 안내는 쉬어도 추운 자리에서만 붙인다. 실내 내역은 "실내 +5, 날씨를 막아 줌 +5"처럼 나눠 적는다, 12-186), take_action 결과의 추위 줄("추위: 밤 바깥 -7°, 체감 -1° (실내 +4, 방한복 +6)"), 상태 화면 머리의 기온·체감 (체감 8° 아래 노랑, 0° 아래 빨강)
- **겨울 10일 시뮬레이션** (날씨 고정, 낮 4시간 바깥 수색): 불 땐 거점은 한파에도 멀쩡. 폐허 + 방한복·담요는 맑음·눈은 버티고 한파가 이어지면 서서히 나빠지며(9일째 의식불명), 밤에 모닥불을 피우면 한파도 버틴다. 방한복 없이 담요만이면 맑음 9일·눈 4일·한파 2일째 죽음. 방한복·담요로 노숙하면 맑음은 버티고 눈 6일·한파 2일. 맨몸 노숙은 맑은 날도 이틀을 못 넘긴다
- **다른 무리 거점에서 묵기** (12-121, `shelter.guests` 0): 그 무리가 우리 무리를 0 이상으로 보면(무소속은 0, 떠돌이를 먹잇감으로 보는 무리는 -3) 그 거점의 연료가 하루치 이상일 때 불 땐 방에 재워 준다. 갇힌 몸은 손님이 아니다
- **젖은 옷** (12-121, 12-186, `climate.wet`): 비 오는 날 바깥에 있었거나 이야기 효과 `soak`(강·하수구·물웅덩이)로 젖으면 **마를 때까지** 체감 -10 ("젖은 옷 -10"). 시간으로는 마르지 않는다. 마르는 길은 둘
  - 불 곁(모닥불·난로)에 두 시간 (`fire_hours`. 불 곁에 있는 동안은 빼지 않는다)
  - 갈아입을 옷이 있는 곳에서 갈아입기 (`take_action.change_clothes`, 곁의 사람도 함께): 우리 무리의 거점, 내 거처, 옷이 남은 곳(`location.clothes`: 대형 마트 폐허, 언덕 위 성당). 장비 칸을 바꾸는 equip과는 다르다
  - 겨울에는 치명적이다: 비 오는 날 수색하고 불도 갈아입기도 없으면 이틀째 죽는다 (방한복을 입어도 사흘째, 플레이 테스트 6)
  - 보이는 곳: 젖을 때·마를 때 결과 줄("옷: 마름 → 젖음 (비를 맞았다. …)"), GM 기온 줄 끝의 "옷이 젖어 있다 (불 곁에서 N시간 더, 또는 …)", 상태 화면 몸 상태 칩 "젖은 옷"
  - 캐릭터마다 `wet`(불 곁에서 마르기까지 남은 분), 이벤트 `wet_set`. 예전 세이브의 `soaked`는 읽을 때 옮긴다. 세이브 형식 76
- **동행의 추위** (12-122): 함께 다니는 사람(동물·감염체 빼고)도 주인공과 같은 자리·활동의 추위를 겪는다. 옷과 체질·젖은 옷은 그 사람의 것이고, 다른 사람은 장비 칸을 고르지 않으므로 지닌 방한복을 입은 것으로 본다. 끝까지 가면 얼어 죽는다. 거점에 사는 인물은 무리가 불을 때 준다고 보고 계산하지 않는다 (122명 모두에게 돌리면 세계가 크게 흔들린다)
- **땔감 패기** (12-122, 제작 법 `split_firewood`): 판자 하나를 목수 연장이나 마체테로 패서 땔감 둘. 판자를 그대로 태우면 3시간, 패면 8시간 탄다 (목공의 겨울 쓸모)
- **피난처의 난로** (12-122, `climate.sanctuary` 10°): 성당·캠퍼스(location.sanctuary) 실내는 거점(16°)보다 춥지만 10° 아래로 내려가지 않는다
- 거점에 사는 인물의 추위·허기는 12-125에서 넣었다 (4.5.4)

#### 4.5.4 거점에 사는 사람들의 몸 (12-125)

무리의 형편(9.13)이 숫자로만 있지 않고 그 무리 사람들의 몸에 보인다. 규칙은 core `engine/residents.ts`, 상한은 `body.residents` (*임시*)

- **누구**: 무리에 속한 사람 (이름 있는 인물과 엑스트라). 주인공, 동행(주인공과 함께 계산한다), 갇힌 사람, 떠난 사람, 무리 없는 사람, 동물·감염체는 빠진다
- **허기**: 하루마다 그 무리의 배급 수준을 주인공과 같은 규칙으로 (정량 -2, 줄어든 배급은 허기짐까지, 반쪽은 굶주림까지)
- **추위**: 무리의 연료가 하루치보다 모자라 거점에 불을 못 때고, 그날 새벽 기온 + 거점 실내(cover)가 체감 기준(comfort)보다 낮으면 하루 한 단계. 불을 때거나 따뜻하면 한 단계 풀린다
- **죽지 않는다**: 굶주림·오한까지만 (`residents: { hunger_max: starving, cold_max: shiver }`). 사람이 죽는 것은 전쟁 시뮬레이션의 인구 감소(9.4)가 맡는다. 이름 있는 인물이 갑자기 굶어 죽어 세계가 흔들리지 않게
- **보이는 곳**: GM 카드의 상태 줄 ("굶주림", "오한"). GM은 핼쑥함·떨림으로 연기한다. 장면에 있는 사람의 변화만 화면에 알린다
- 소문으로 들은 "붉은연합 식량이 바닥났다"가 그 땅에 가면 실제로 굶주린 사람들로 보인다

- **주인공도 같은 한도** (12-138): 우리 무리 거점의 실내에 있는 동안은 주인공(과 동행)의 추위도 `cold_max`에서 멈춘다. 연료가 바닥나도 사람들이 모여 버틴다. 전에는 같은 방의 거점 사람은 오한에서 멈추는데 그 사람을 이어받은 주인공만 얼어 죽어, 간부가 연료를 다 쓴 판에서 계승이 1~4일 만에 연달아 끊겼다. 한도에 걸린 냉기는 쌓아 두지 않는다. 바깥은 그대로 위험하다

#### 4.5.3 피로 (12-114)

잠과 휴식이 시간만 보내는 일이었다. 며칠을 안 자고 수색과 보초를 이어 가도 손해가 없었다. 깨어 있은 시간을 쌓아 단계로 바꾼다 (기온의 냉기와 같은 틀). 규칙은 core `engine/fatigue.ts`, 수치는 `body.fatigue` (*임시*). 주인공만 계산한다

- **쌓임**: 깨어 있으면 시간당 1. 잠(`sleep`)은 시간당 -3(6시간 자면 18이 풀린다), 휴식(`rest`)은 0(더 쌓이지 않을 뿐). 0 아래로는 내려가지 않는다. 캐릭터마다 `fatigueLoad` (세이브 형식 44)
- **단계** (트랙 `fatigue`): 개운함 → 졸림(16시간, 보정 없음) → 지침(24시간, -1) → 탈진(32시간, -2). 단계는 쌓인 것에서 바로 정해지므로 레벨의 버팀으로 피하지 않는다. **피로로 죽지 않는다** (끝 단계에 fatal이 없다)
- 보통 하루(아침에 일어나 16시간 깨어 있고 6시간 잔다)는 저녁에 졸리고 자고 나면 개운하다. 밤을 새우면 다음 날 지치고, 이틀을 새우면 탈진한다
- **보이는 곳**: 상태 줄과 판정 줄(`-1(지침)`), 졸림 이상이면 GM 상태에 "피로: 깨어 있은 지 오래다 … 자면 풀린다" 줄. 상태 화면 아이콘 `moon`
- 자동 플레이는 지치면(지침 이상) 70% 확률로 잔다. 무작위로만 고르면 표본의 42%가 탈진이었다 → 넣은 뒤 개운함 73%, 졸림 23%, 지침 4%
- **자야 낫는다** (12-115, `blocks_recovery_from: weary`): 지침 이상인 동안은 부상이 저절로 낫지 않고(4.4. 이틀이 차도 기다린다. 자고 나면 밀린 만큼 바로 낫는다), 질병이 낫는 조건 "배부르고 따뜻하면"에 "지치지 않았으면"이 더해진다 (하루 틱은 자정이라 보통 하루면 졸림이고, 밤을 새운 날만 막힌다). 의식불명에서 깨어나는 것과 치료사·소모품은 그대로. GM의 피로 줄에 함께 알린다
- **몸을 쓰는 일은 더 지친다** (12-119, `rates`): 이동·수색·작업 시간당 1.5, 전투 3 (보초·기다림·대화는 1). 고된 하루(8시간 몸을 쓰고 8시간 가볍게)는 20이라 저녁에 졸린다
- 넣지 않은 것: 몸이 좋을 때의 보너스(4.2에서 보류), NPC의 피로

#### 4.5.5 먹고 마시기: 사냥·낚시, 덫, 부패, 끓이지 않은 물 (12-131)

배급과 수색 말고도 먹을 것을 직접 구하고, 구한 것을 지키는 일. 무엇을 얼마나 얻는지·상하는지·병에 걸리는지는 코드가 정한다 (시나리오 `foraging`·`spoilage`, 아이템 `perishable`·`contaminated`)

- **사냥·낚시** (`take_action.forage`): 판정 결과만큼 얻는다 (수색과 같다: 성공 2, 대가 있는 성공 1, 실패·판정 없음 0, 12-220). 일의 쉽고 어려움은 판정 보정(`kinds[].modifier`, 낚시 +1)이고, 같은 날 같은 구역에서 다시 할 때마다 판정 -1. 낚시는 물이 나는 구역에서(날생선 1~2), 사냥은 거점이 아닌 구역에서(날고기). 수색만큼 시간이 든다
  - 개(떠돌이 개 틀)가 동행하면 사냥에서 한 번 더 굴린다. 낚시 도구는 원래 생존 +1
- **덫** (`take_action.trap: set | check`): 철사 한 뭉치를 놓는다 (구역마다 하나, 거점 안은 안 된다). 놓는 판정이 성공이면 다음 날, 대가 있는 성공이면 이틀 뒤에 날고기가 걸린다 (12-220, 숨은 확률 없음). 다시 가서 거두면 걸린 것과 철사가 돌아온다. GM 상태에 "이 구역에 놓아 둔 덫"
- **부패**: 하루가 지날 때 주인공이 가진 날것 하나하나가 `perishable` × 계절 배수(여름 1.5, 겨울 0.4)로 상해 없어진다. 날생선·날고기 0.4, 들풀 0.3, 버섯 0.25, 토마토 0.15, 오이 0.1, 사과 0.05, 감자 0.02. 통조림·건빵·말린 것·훈제는 상하지 않는다
  - 훈연 제작법: 날생선 둘 + 땔감 → 말린 생선 둘, 날고기 둘 + 땔감 → 훈제 고기 둘 (생존)
- **끓이지 않은 물**: 바깥의 물이 나는 곳에서 그냥 마시면 15%로 병(질병 잠복)에 걸린다. 채우면 "끓이지 않은 물병"이 되고, 마실 때 같은 확률. 그 구역에 모닥불이 피어 있으면 끓여 마셔 괜찮다 (채우면 깨끗한 물병). 우리 거점의 보급은 깨끗하다
- 수치는 모두 *임시*. 세이브 `traps`, 이벤트 `trap_set`·`trap_caught`·`trap_collected`. 세이브 형식 50. core `engine/forage.ts`

#### 4.5.6 야영과 불침번 (12-148)

바깥에서 자는 것이 기온(4.5.2)과 피로(4.5.3)만의 문제였다. 지붕 없는 곳의 밤에 무엇이 다가오는지, 누가 지키는지를 넣는다. 규칙은 core `engine/camp.ts`, 수치는 `scenario.camp` (*임시*)

- **야영인 곳**: 지켜 주는 지붕이 아닌 곳. 지켜 주는 지붕은 우리 무리 거점, 손님으로 재워 주는 다른 무리 거점(12-121의 조건, 연료와 상관없이), 피난처(`sanctuary`)다. 갇힌 동안은 야영이 아니다
- **밤의 일**: 야영인 곳에서 자기·쉬기·기다리기·보초(`sleep` `rest` `wait` `guard_duty`)를 하는 동안, 구역의 위험(위험과 감염체 압력 중 높은 쪽)별 시간당 확률(`chance` 0.01·0.03·0.06·0.1)로 태그 `camp` 이야기 하나가 열려 그 시간을 끊는다. 6시간 자면 위험 0: 6%, 1: 17%, 2: 31%, 3: 47%. 이야기 사이 간격과 상관없다 (길 위의 일과 같다). 끊긴 잠은 마음을 가라앉히지 않는다 (12-95)
- **모닥불** ×1.5 (`fire`, 불빛과 연기), **우리 땅** ×0.5 (`own_land`, 우리 순찰이 돈다)
- **불침번**: 깨어 있는 활동이거나, 곁에 보초를 설 동행(깨어 있는 사람·동물. 끌고 가는 포로·감염체는 빠진다)이 있으면 지켜보는 밤이다. 이야기 조건 `camp_watched: true`는 다가오는 것을 먼저 아는 이야기, `false`는 아무도 지키지 않고 잠들어 이미 가까이 와서야 깨는 이야기다. 혼자서 지키려면 보초(`guard_duty`)를 서고 그동안 잠은 못 잔다 (피로가 쌓인다). 동행의 피로는 계산하지 않는다 (4.5.3)
- **깊은 잠** (12-188, `camp.deep_sleep`: 피로 지침·질병 고열·부상 중상 이상, *임시*): 잠들 때 몸이 이러면 보초를 설 동행이나 경보줄이 있어도 지켜보지 않는 밤으로 친다 ("보초를 서던 ○○이 흔들어 깨웠지만 몸이 무거워 이미 가까이 와서야 깼다"). 급한 이야기에 깨면 GM에게 "몸이 무거워 늦게 깼다"를 붙인다. 밤손님이 오는 확률과 이야기가 열리는 것은 그대로다 (이야기를 건너뛰지 않는다). 지켜보는 밤에만 열리는 이야기는 그날 밤 후보에서만 빠진다. GM 잠자리 줄에 "지금 자면 깊이 잠든다"를 미리 알린다
- **조건**: `camp_watched`, `campfire`(모닥불이 타는지), `camp_danger_gte`·`camp_danger_lte`
- **보이는 곳**: 저녁·밤·새벽에 야영인 곳에 있으면 GM 상태에 "잠자리" 줄 (보초를 설 수 있는 동행, 모닥불의 불빛, 우리 땅인지. 숫자는 없다). 이야기가 열리면 결과에 "야영지에 일이 생겼다"와 누가 먼저 알아챘는지
- **콘텐츠** (`storylets/camp.yaml` 10개): 지켜보는 밤(냄새를 맡는 감염체, 불가로 오는 사람, 불빛을 본 남의 땅 순찰, 졸던 보초, 어둠 속의 아이 울음), 아무도 지키지 않은 밤(눈을 뜨니 곁의 감염체, 짐을 뒤지는 손, 갉는 쥐), 어느 쪽이든(들개 떼, 비 오는 밤 스며드는 빗물)
- 넣지 않은 것: 숨을 자리 고르기 판정, 빛과 냄새의 따로 된 규칙(모닥불의 배수로 대신한다), 교대 보초로 줄어드는 잠

### 4.6 트레잇 (12-10)

림월드·프로젝트 좀보이드처럼 캐릭터마다 몇 개의 **트레잇**(타고난 기질·버릇·체질)이 있다. 능력·스킬이 "얼마나 잘하나"라면 트레잇은 "어떤 사람인가"다. 플레이어와 NPC가 같은 트레잇을 쓴다 (원칙 6)

**세 종류**

- **긍정** (비용 1~2): 이득이 있는 기질·체질
- **부정** (보상 1~2): 손해가 있는 기질·체질. 골라서 포인트를 얻는다
- **성격** (0): 수치 효과가 거의 없고 연기에 쓰는 기질. NPC의 `temperament`(warm, guarded …)를 이것으로 옮긴다

**캐릭터 생성** (웹 생성 화면, MCP는 GM이 묻는다)

- 긍정·부정은 **트레잇 포인트**로: 고른 긍정 비용의 합 ≤ 고른 부정 보상의 합 (부정을 골라야 긍정을 고를 수 있다). 긍정·부정 각각 최대 3개
- 성격은 공짜로 최대 2개
- 서로 반대인 트레잇은 함께 고를 수 없다 (예: 추위에 강함 ↔ 추위를 탐)
- 능력 포인트(4)와는 따로 센다
- "무작위"는 규칙에 맞게 고른다. 고르지 않으면 트레잇 없이 시작한다 (MCP의 "알아서"는 무작위)

**효과** (core는 효과 종류만 안다. 어떤 트레잇이 무엇을 하는지는 시나리오 팩 `traits` 데이터)

**NPC 연기**

- NPC 16명의 `temperament`를 트레잇(성격 + 필요하면 긍정·부정)으로 옮긴다. 예: 강태호 = 원칙주의·신중함·강심장, 오지호 = 수다쟁이·열성적·겁쟁이
- GM 상태의 인물 줄에 트레잇 이름과 연기 지침이 나온다 (지금은 영어 단어 `warm, guarded`). 플레이어 캐릭터의 트레잇도 GM 상태에 나와 서술에 반영된다 (겁쟁이면 망설이는 묘사)
- 트레잇은 겉으로 드러나는 것과 아닌 것이 있다: 처음 만난 인물의 트레잇은 겉으로 보이는 것(`visible`)만 플레이어에게 보인다 (`?인물`, 시트). GM은 연기를 위해 다 안다 (NPC 프로필은 원래 GM이 아는 정보다)

**구현** (12-10)

- 시나리오: `traits` 목록(id, 이름, 종류, 비용, 설명, 연기 지침 `acting`, 겉으로 보이는지 `visible`, 반대 `opposites`, 고를 수 있는지, 효과). `creation.traits`에 종류별 최대 개수. post_apoc은 긍정 12·부정 10·성격 24개
- core: 효과는 `engine/traits.ts`가 읽는다. 판정(스킬 보정은 상한 안, 끌림은 `check_rolled.modifiers.trait`로 따로), 성장(경험치 배수), 몸(허기·추위·질병·감염·저절로 낫기), 목격(들킬 확률·주의력), 소문(옮길 확률. 예전 `talkative` 하드코딩을 대신한다), 첫인상(매력 + 외모·끌림·질투), 호감 변화(끌림 +1, 질투 -1)
- 생성: `checkTraits`(겹침·반대·최대·포인트), `randomTraits`. 웹 생성 화면에 종류별 칩(못 고르는 것은 꺼짐), MCP는 생성 안내에 목록과 규칙. `character.traits`가 null이면 무작위
- NPC 16명의 `temperament`를 트레잇으로 옮기고 체질·외모·이성편력을 더했다 (예: 마경수 = 잔혹함·인내심·아름다운 외모·이성편력, 탁봉수 = 넉살·계산적·이성편력·말재간)
- 보이는 곳: GM 상태(플레이어 트레잇과 NPC 트레잇의 연기 지침, 끌림·질투 줄), `?상태`, `?인물`(만나 본 인물의 보이는 트레잇만), 웹 시트(트레잇 칩), 판정 카드(트레잇 보정)
- 이전 세이브: 캐릭터 `traits`는 빈 목록으로 읽고, NPC는 콘텐츠의 트레잇을 쓴다. `SAVE_SCHEMA_VERSION` 5

**처음 정한 영향 범위**

- 시나리오: `traits` 목록(id, 이름, 종류, 비용, 효과, 반대, 연기 지침, 겉으로 보이는지). `creation`에 트레잇 규칙(최대 개수)
- 캐릭터: `traits: string[]` (이전 세이브는 빈 목록, NPC는 콘텐츠에서). `SAVE_SCHEMA_VERSION` 5
- 콘텐츠: NPC 16명 `temperament` → `traits`, 역할은 시작 트레잇 없음
- 생성 화면·MCP 생성 안내에 트레잇 고르기, 시트·`?상태`·슬롯에 트레잇
- 효과가 들어가는 곳: 판정(스킬 보정), 성장, 몸 상태(허기·추위·질병·감염·회복), 목격자, 소문, 첫인상

#### 4.6.2 버릇: 골초 (12-129)

기호품을 중독 규칙 없이 트레잇 하나로 다룬다. 담배는 원래 거점에서 돈처럼 쓰이는 물건이라, 골초는 "피울 것이냐 흥정에 쓸 것이냐"를 고민하게 된다.

- 담배 트랙은 `quiet`: 처음 단계(이상 없음)면 상태 문장에 나오지 않는다 (골초가 아닌 사람에게 "담배: 이상 없음"이 붙지 않게)
- **골초**(부정, 보상 2. 담배가 귀해 안절부절을 오래 달고 살 수 있다): 하루가 지날 때 담배 한 갑(`cigarettes` 하나)을 저절로 피운다. 가진 게 없으면 **안절부절**(판정 -1, 다른 몸 상태처럼 모든 판정에)
- 안절부절은 담배를 피우면(`use_item`) 바로 풀리고, 다음 날 담배가 있으면 저절로 피우며 풀린다. 한 단계뿐이고 더 나빠지지 않는다
- 참는 일이라 버팀(레벨)으로 피하지 않는다
- 새 캐릭터는 담배 세 갑을 들고 시작한다 (`start`)
- 시나리오: 트레잇 효과 `habit: { items, track, start }`, 상태 트랙 `craving`(담배), 증상 `restless`, `consumables.cigarettes: { craving: 1 }`. core는 담배를 모르고, "하루에 하나씩 쓰고 없으면 트랙이 오른다"만 안다. 술꾼 같은 다른 버릇도 같은 효과로 만든다

#### 4.6.3 술·진통제·마약 (12-157)

골초(4.6.2)의 버릇 틀에 "기운"과 "의존"을 더했다. 쓰면 당장 편해지고, 자꾸 쓰면 몸이 찾게 된다.

- **기운** (`body.wear_off`): 술기운·진통·각성 트랙. 소모품이 트랙을 올리고(`consumables`에 음수), 마지막으로 바뀐 뒤 정한 시간마다 한 단계씩 빠진다 (술 3시간, 진통제 4시간, 각성제 5시간, *임시*). 기운을 올리는 소모품은 나아질 데가 없어도 쓸 수 있다. 장면의 모든 사람에게 같다
- **가리기** (증상 `masks`): 기운의 증상이 있는 동안 그 묶음 증상의 판정 보정이 빠진다. 증상은 그대로 보인다 (상처가 낫는 것이 아니다)
  - 진통제(진통 1단계, 4시간)·모르핀(2단계, 8시간): 고통을 가린다
  - 소주(술기운 1)·밀주(2): 얼큰함은 공포를 가리고, 취함은 공포를 가리되 판정 -1, 더 마시면 메스꺼움
  - 각성제(각성 2단계, 10시간): 피로를 가린다. 피로는 그대로 쌓인다
- **의존** (`body.dependence`): 쓸 때마다 확률로 버릇 트레잇이 붙는다 (소주 3%, 밀주 5%, 진통제 5%, 모르핀 20%, 각성제 15%, *임시*). 술꾼은 처음부터 고를 수도 있다 (보상 1, 소주 두 병을 들고 시작). 진통제 의존·각성제 중독은 고를 수 없다
- **금단**: 버릇 트랙이 두 단계다. 하루치를 못 하면 안절부절(-1), 다음 날 손떨림·금단 증상(-2, 약은 메스꺼움, 각성제는 지침이 함께)
- **끊기** (`habit.quit_days`): 끝 단계를 정한 날만큼 버티면 트레잇이 빠지고 트랙이 처음으로 (술꾼 10일, 진통제 7일, 각성제 14일). 골초는 끊는 날이 없다
- 구할 곳: 수색표(거점·구시가·장터·진료소·옛 병원·휴게소·고가도로·지하철·캠퍼스). 모르핀은 옛 병원에서만, 각성제는 장터·지하철·캠퍼스에서 드물게

#### 4.6.1 성격 축 (12-99)

주인공의 성격을 목록에서 고르는 대신 **인성검사처럼 축마다 단계로** 정한다. 플레이어와 캐릭터의 성격이 달라도 캐릭터다움이 유지되게 하는 것이 목적이다. 말투와 태도는 GM이 성격대로 연기하고, 성격이 행동·관계에 결과를 남기는 순간은 코드가 정한다 (원칙 2, 5)

- **축** (월드 팩 데이터, 원칙 7. *임시*): 온화함 ↔ 다혈질, 과묵함 ↔ 수다스러움, 신중함 ↔ 충동적, 차가움 ↔ 다정함, 원칙적 ↔ 실리적, 금사빠 ↔ 돌부처. 축마다 -2 ~ +2 (`온화함 2 1 0 1 2 다혈질`), 기본 0. 능력·트레잇과 겹치는 축(대담 ↔ 소심 = 냉정 능력, 겁쟁이·강철 신경)은 두지 않는다. 단계마다 GM용 연기 설명을 데이터로 둔다
- **금사빠 ↔ 돌부처** (연애, 12-58): 호감이 연애 감정으로 얼마나 빨리 넘어가는가
  - NPC: 연애 문턱(`interest_affection`)과 고백 수락 조건에 더하고 뺀다 (금사빠는 금방 마음이 생기고, 돌부처는 호감이 높아도 좀처럼 넘어가지 않는다). 코드가 계산한다
  - 주인공: 말투·태도만 ("주인공의 마음은 플레이어가 정한다"). 금사빠 2면 매력적인 인물 앞에서 말이 꼬이고 눈길이 간다 "(금사빠)", 돌부처 2면 호감을 보여도 무덤덤하게 받아넘긴다
  - 연애는 수위와 상관없으므로(12-100) 이 축도 늘 쓰인다
  - 이성편력 트레잇과는 따로다: 이성편력은 **끌림**(외모 좋은 이성에게 첫인상 호감 ×2, 이성의 설득·거짓말에 약함, 숨은 성격)이고 이 축은 **마음**(정이 들면 빠지는 빠르기)이다. 외모에 혹하지만 마음은 안 주는 사람(이성편력 + 돌부처)도 있다. 이성편력은 축으로 옮기지 않고 숨은 약점 트레잇으로 남긴다
- **0은 플레이어 뜻대로, 2는 캐릭터가 강하게**: 캐릭터를 직접 연기하고 싶은 플레이어는 0에 가깝게 둔다
- **누가 정하나: "어떻게"와 "무엇"을 나눈다**
  - 말투·태도·말의 양 → GM이 성격대로 연기한다. 무뚝뚝(과묵 2)이면 플레이어가 길게 말해도 짧게 끊고, 다혈질 2면 같은 지시도 거칠게 나온다
  - 결과가 없는 행동이 끼어드는 것 → GM 연출. 문을 발로 차 연다 (문이 열리는 결과는 같다). 공격·거래 성사·약속처럼 결과가 남는 일은 끼워 넣지 않는다
  - 성격이 터지는 순간 → **코드가 판정한다**. 도발을 받으면 다혈질 값만큼 "발끈" 확률, 대화 중 수다스러움 값만큼 아는 사실 하나가 새어 나갈 확률. 터지면 관계 변화·정보 누설을 코드가 고르고 적용하며, 숨은 사실은 정보 필터를 거친 것 중에서만 고른다 (원칙 4)
  - 관계 → 처음 만날 때·대화할 때 성격 궁합(예: 원칙적인 NPC와 실리적인 주인공)으로 호감이 조금 오르내린다 (외모의 첫인상과 같은 방식, 코드가 계산)
- **보이게 한다**: 플레이어가 말하지 않은 행동·말이 성격 때문에 생기면 이유를 붙인다
  - 말투·태도만 바뀜 → 표시 없음
  - GM 연출로 끼어든 행동·말 → 문장 끝에 꼬리표: "서진은 문을 발로 차 열었다 (다혈질)"
  - 코드 판정으로 결과가 남음 → 판정 줄처럼 코드가 만든 한 줄을 그대로 옮긴다: `🎭 다혈질 2: 발끈했다 · 강태호의 호감 -1`
  - 꼬리표는 한 턴에 한두 번까지. 값 1이면 가끔, 2면 자주 드러낸다
- **NPC와 같은 틀** (원칙 6): 캐릭터의 `persona`(축 값). NPC는 비어 있고(null) 성격 트레잇마다 매긴 축 값(`traits[].persona`, 다혈질 → temper +2, 무뚝뚝 → talk -2 …)을 더해 -2~2로 자른다. 콘텐츠의 NPC·엑스트라는 그대로 성격 트레잇을 쓰고, 숨은 성격(`visible: false`)의 정보 필터도 트레잇 그대로다. 사망 뒤 NPC로 이어 가면 그 NPC의 트레잇에서 나온 축 값을 쓴다
- **빈 축 채우기** (12-101): NPC의 성격 트레잇이 정하지 않은 축은 인물 id에서 `persona.fill`의 무게로 뽑는다 (판마다 같다. 대부분 0이나 ±1, ±2는 드물고, 트레잇이 없는 금사빠 ↔ 돌부처는 더 넓게). 트레잇이 정한 축과 직접 적은 `persona`가 우선한다. NPC 122명: 모든 축이 0인 인물 1 → 0, 성격이 붙은 축 평균 2.5 → 4.6개, 서로 다른 조합 71 → 117가지, 금사빠 ↔ 돌부처는 모두 0 → 고르게. NPC·엑스트라 카드에 "성격: …" 줄 (GM이 말투·태도에 반영)
- **말투와 맞추기**: 인물 데이터의 `persona`에 바꿀 축만 적으면 그 축만 덮어쓴다 (나머지는 트레잇과 빈 축 채우기). NPC 122명의 말투·원하는 것·두려움과 대조해 어긋난 22명을 고쳤다 (차분한 존댓말인데 다혈질, 크고 빠른 말투인데 과묵 2 등). 금사빠 ↔ 돌부처는 말투로 판단할 근거가 없어 두었다
- 검토했지만 넣지 않은 것: 축마다 보이는 값과 속 값(겉과 속), 상태에 따라 흔들리는 성격(기분). 인물은 깊어지지만 규칙과 GM이 따질 것이 늘어 복잡해진다. 깊이는 원하는 것·두려움·비밀·가치관 같은 기존 인물 데이터가 맡는다
- **기존 성격 트레잇과의 관계**: 캐릭터 만들기의 "트레잇: 성격" 단계를 축 정하기로 바꾼다. 규칙 효과가 있던 둘은 트레잇으로 남는다: 수다쟁이의 소문 ×2는 NPC가 소문을 옮길 때 그대로 쓰고(축 값 talk +2도 준다), 이성편력은 숨은 약점 트레잇이다 (금사빠 ↔ 돌부처와 따로)
- **만들기 화면**: 축마다 다섯 칸 버튼, 기본 0. 채팅은 "온화함 ↔ 다혈질: -2 ~ +2" 목록을 한 번에 보여 주고 한 줄로 답하게 한다 ("다혈질 2, 과묵 1"). 둘 다 core가 검증한다
- **GM 상태**: "성격: 다혈질 2(같은 지시도 거칠게, 도발에 쉽게 발끈), 과묵 1(말을 아낀다). 플레이어가 말하지 않은 행동·말을 성격으로 넣으면 (다혈질)처럼 꼬리표를 붙인다"
- **구현** (core `engine/persona.ts`, 수치는 `scenario.persona`, *임시*): 발끈은 GM이 `take_action.provoked`(누가 도발·모욕했으면 true, 그 사람을 target으로)를 넘기면 다혈질 1이면 25%·2면 50%로 굴리고, 터지면 상대의 호감 -1. 말 새어 나감은 장면의 인물과 `talk` 활동을 하면 수다스러움 1이면 10%·2면 25%로 굴리고, 터지면 주인공이 아는 사실(믿음) 중 그 인물이 모르는 하나를 그 인물이 알게 된다 (주인공이 아는 것만이라 정보 필터를 지킨다). 궁합은 처음 만날 때 다정함·원칙 축이 같은 쪽이면 +1, 반대쪽이면 -1 (합 -2~2). 연애 문턱은 NPC의 금사빠 ↔ 돌부처 1단계마다 1. **손해가 있는 쪽엔 득도 있다** (12-107, 그전엔 다혈질·수다는 손해뿐이라 온화·과묵이 무조건 나았다): 다혈질(+쪽)이면 위협 판정 +1(`persona.edges`, 끌림처럼 상한 밖, 판정 줄에 "다혈질 1"로), 수다스러우면 같은 확률로 상대가 아는 사실(믿음, GM에게 "물으면 말해 줄 수 있다"로 보이는 것) 중 주인공이 모르는 하나를 얻어듣는다(`persona.hear`). 낮은 쪽(온화·과묵)은 손해도 득도 없는 무난한 선택. 신중↔충동은 규칙이 없어 치우치지 않는다. 🎭 줄은 결과 끝에 "성격 줄"로 실린다. 성격 트레잇을 고르던 만들기 단계는 축 정하기로 바뀌고(성격 축이 있는 월드), 운에 맡기는 트레잇도 성격을 뽑지 않는다. 세이브 형식 41

#### 4.6.4 캐릭터 설정 (RP, 12-246)

성격 트레잇(기질: 어떻게 말하고 대하나)과 함께 가는 **설정**(내용: 무엇을 믿고, 하지 않고, 몸에 배었나). 재밌는 RP를 위한 것이라 보상은 없다. 목록 초안은 `docs/settings-draft.md`.

- **칸과 개수** (모두 선택, 전부 비워도 됨, 직접 쓰기 없이 목록에서만): 이상 0~1, 금기 0~2, 결점 0~2, 버릇 0~2, 말투 0~1, 비밀 0~1, 소중한 것 0~1. 목록은 시나리오 팩(`scenario.yaml`의 `settings`)에 칸마다 12~20개, core는 칸 종류만 안다(원칙 7). 항목마다 이름·한 줄 설명·연기 힌트, 이상·금기·결점은 확인 말("복종을 신념으로 가진"). 정면으로 모순되는 짝만 함께 고르지 못한다
- **거스를 때 굴림** (이상·금기·결점만): GM이 플레이어 행동이 설정을 거스른다고 보면 굴리기 전에 서술로 먼저 확인한다("복종을 신념으로 가진 김혁진은 이 선택이 마음에 걸린다. 정말 이렇게 해야 할까?", 도구 없이 지침으로, 엔진이 강제하지 않음). 물러서면 굴림 없음. 그래도 하면 GM이 도구에 `against_setting`을 넣고 코드가 정신력(nerve)으로 굴린다: 성공 뜻대로 / 대가 있는 성공 뜻대로 하되 마음 한 단계 흔들림 / 실패 GM이 행동을 바꾸고 까닭을 짧게. 같은 장면에서 같은 설정은 한 번만(이겨 냈으면 다시 막지 않음). 성장 장면이면 굴리지 않아도 된다. 버릇·말투·비밀·소중한 것은 굴리지 않는다
- **대사 조미료**: 모든 설정을 GM이 대사에 조금씩 녹인다. 알리지 않는다 (성격 꼬리표와 다름)
- **성격 조건**: 성격을 구체화한 설정(결점 대부분, 일부 말투)에 `requires: { 다혈질: 2 }`(1 가끔, 2 자주). 고르는 화면(상태 화면·채팅)에 "다혈질 2 필요", "함께 고를 수 없음: ○○"을 보이고 못 채우면 흐리게·선택 불가. 만들 때만 보는 제약(이후 성격이 바뀌어도 설정은 유지). 성격과 같은 말을 하는 설정은 빼거나 상황이 붙게 쓴다
- **주인공·NPC 공통** (원칙 6): 설정은 캐릭터 스키마 하나. NPC 콘텐츠에 `settings` 선택 칸, 기존 자유 글 `rules`·`voice`는 그대로 두고 GM 카드에 함께. NPC에게는 굴림 없음
- **모듈화**: 공통 규칙 16 "자기다움"(`rules/self.ts`): 성향이 플레이어 뜻을 꺾는 굴림(발끈·새어 나감·얻어들음·설정 거스르기)을 한 곳에, 결과 매핑·결과 줄·같은 장면 한 번 제한, 판정 값은 공통 규칙 12 `attemptValue(reaction)`. 연기 카드 함수 하나(성격·설정·말투, 사람 정보 한 곳처럼), 대사 조미료(알림 없음)와 성격 꼬리표(알림)의 차이도 여기서. 비밀은 NPC 비밀 장치(revealedSecrets·reveal_secret·신뢰 조건)를 다시 쓴다(처음엔 아무도 모름, 누가 아는지는 공통 규칙 7·14, 들키는 판정은 새로 만들지 않는다). 마음 흔들림은 `changeCondition`, 장면 경계는 공통 규칙 15
- **비밀 (GM이 실수하지 않게)**:
  - 항목마다 **사실**(숨겨진 진실 한 문장, GM만 봄)과 **연기 힌트**(겉으로 보이는 낌새)를 나눈다. GM 상태에는 "당신만 아는 비밀: (사실). 아는 사람: 없음 (NPC는 아는 듯 말하지 않는다)"로 싣는다
  - 정보 필터(원칙 4): 비밀은 아는 사람의 인물 카드에만 실린다. 알게 되는 길은 둘뿐: 주인공이 털어놓음(`reveal_secret { own: true }`: 털어놓은 상대와 그 자리에 있던 사람이 안다, 공통 규칙 7), 뒷받침된 지난 일(탈영병을 아는 그 무리처럼). 서술만으로는 아무도 알게 되지 않는다(GM 지침). 아는 사람이 생기면 소문은 공통 규칙 14로
  - **지금 세계에 무언가가 있다고 말하는 비밀은 엔진 상태로 뒷받침한다**(원칙 2): 탈영 → 지난 일 `deserter`, 빚 → `debt`, 적 무리의 가족 → `kin_alive`, 빼돌린 식량 → 우리 거점 사물함, 약 의존 → 트레잇 `pill_habit`. 지나간 일만 말하는 비밀은 아무것도 남기지 않는다. 세계에 없는 것을 꾸며야 하는 비밀(숨은 금고, 지금도 이어지는 밀정 노릇)은 넣지 않는다
  - NPC의 기존 `secret`(content·reveal_when·min_trust)과 같은 틀로 합친다. 기존 NPC로 이어 가면 그 사람의 비밀이 주인공의 비밀이 된다
- **시나리오의 정해진 사연·트레잇과 부딪힘** (조사: 시나리오 역할의 지난 일(`history`·`background`·`family`·`start_debt`), 성격 축, 트레잇):
  - 같은 말이거나 모순인 트레잇과 함께 고르지 못한다(`trait_opposites`): 어둠 공포 트레잇이 있어 "어둠이 무섭다" 결점은 뺐다. 술꾼 ↔ 술을 끊음, 개 공포 ↔ 짐승을 먹인다, 냉소적 ↔ 사람을 잘 믿는다. 진통제 의존은 트레잇을 함께 주는 비밀로
  - 성격 축과 같은 말을 하는 항목은 빼거나 상황을 붙였다(차가움 = "남의 일에 무심", 과묵함 = "단답", 수다스러움 = "이야기가 샌다" 등)
  - 시나리오의 정해진 사연과 맞지 않으면 고를 수 없다(`roles_none`·`needs_faction`): 가족을 모두 잃은 청솔형제단 신병·가족이 버들마을에 있는 방문자는 "가족이 적 무리에", 붉은연합 시나리오는 "약탈자였다"(비밀이 아니다), 무소속(떠돌이)은 "무리를 팔지 않는다"·"복종"·"빼돌린 식량", 탈영한 그 무리의 시나리오는 "탈영"
  - 고를 수는 있지만 그 시나리오의 일과 자주 맞서는 것은 화면에 "이 시나리오와 자주 부딪힘"을 보인다(`clashes_roles`): 붉은연합 약탈조·동무조의 "훔치지 않는다"·"사람은 죽이지 않는다"·"사람을 가두지 않는다". 막지 않는다(그 갈등이 이야기다)
  - 이야기 선택지가 설정과 반대인 것(배신을 고르는 선택지 등)은 부딪힘이 아니라 굴림의 자리라 고치지 않는다
  - `content:check`가 조건의 성격 이름, 트레잇 id, 시나리오 id, NPC 설정의 조건 충족을 검사한다
- **그 밖**: 소중한 것은 그 물건을 시작 소지품으로(keepsake, 값으로 나가지 않음, 잃어도 따로 결과 없음). 계승: 기존 NPC로 이으면 그 사람의 설정을 이어받고, 새 캐릭터면 만들기에서 고른다. 만들기 순서: 성격 트레잇 다음 "설정" 단계, 칸마다 고르거나 건너뛰기, "모두 건너뛰기". 성격과 설정 단계에 한 줄 설명. `content:check`가 조건의 성격 이름과 NPC 설정의 조건 충족을 검사한다

### 4.7 수색과 찾을 거리 (12-17)

폐허·창고를 뒤지면(`take_action`의 `activity: search`) 코드가 그 구역의 찾을 거리 표(`locations/*.yaml`의 `loot: { modifier, items: [{ item, weight, qty }] }`)에서 고른다. core `engine/scavenge.ts`.

- **수색 범위** (12-355, 사용자 결정, `scenario.search_scopes`, *임시* 수치): GM이 뒤질 대상의 크기대로 고른다(`activity.scope`, 없으면 방 하나). 칸(장소) 전체를 한 번에 뒤지는 범위는 없다: 뒤질 대상을 정한다 (녹슨 버스 줄이면 버스 한 대씩)
  | 범위 | 예 | 시간 | 찾는 수 (성공 / 대가 있는 성공 / 실패) |
  |---|---|---|---|
  | 방 하나 `room` | 약국 같은 작은 가게, 조제실, 사무실, 버스·차 안, 골목 한 구간, 마당 한쪽 | 15분 | 1~3 / 1 / 0 |
  | 건물 한 층 `floor` | 작은 건물 전체, 빌딩 한 층, 주차장, 넓은 마당 (큰 건물은 층마다) | 60분 | 2~5 / 1~2 / 0 |
  - "찾는 수"는 찾을 거리 표에서 뽑는 횟수다 (한 번마다 그 물건의 수량 범위가 따로 있다). 범위 안의 수는 주입 가능한 난수로 정한다
  - 대가 있는 성공은 그 범위 시간의 절반이 더 든다 (5분 단위로 올림). 대가는 시간이고 다치지 않는다
  - 실패는 "못 찾음"으로 끝난다: 시간만 쓴다. tool 결과가 GM에게 다침·새 위협을 지어내지 말라고 알린다 (일반 판정의 "상황이 악화된다" 대신)
  - 찾을 거리 표대로만 나온다. 임무로 찾는 자원도 따로 보장하지 않는다 (12-227의 보장을 뺐다: 약을 찾으러 가도 잡동사니만 나올 수 있다). 못 구한 임무는 "찾아보았으나 구하지 못함"(12-350)으로 탓하지 않는다. content:check가 구해 오는 임무(`bring`)의 자리 표에 그 자원이 있는지 본다 (`content/bringLoot.ts`)
  - 먹을 것 구하기·덫은 범위와 따로다 (예전 수색 시간)
  - 월드 팩에 `search_scopes`가 없으면 예전대로 (60~120분, 성공 2·대가 1)
- **수색의 다침** (12-355): GM은 정말 위험한 곳에서만 위험을 건다. 코드가 수색의 위험을 가벼운 위험까지로 줄이고, 그날 그 칸 수색으로 한 번 다쳤으면 같은 칸 수색에는 위험을 걸지 않는다(`zoneSearches[칸].hurt`)
- **경험치**: 같은 칸을 같은 날 다시 뒤지는 수색은 "시간을 들인 활동"으로 경험치를 주지 않는다 (한 번만. 위험·임무 같은 다른 걸린 것은 그대로)
- 판정 보정(판정 줄에 보인다): 구역의 넉넉함 `loot.modifier`(털린 곳 -1, 넉넉한 곳 +1), 같은 날 다시 뒤진 양만큼 -1(상태의 `zoneSearches`, 범위가 있으면 `deplete_minutes`(15분)마다 1: 방 하나 1, 건물 한 층 4), 역사를 익혔으면 +1(`search_lore.bonus`)
- 찾은 것은 바로 소지품에 들어온다. GM은 결과에 나온 것만 서술한다 (원칙 2)
- 무소속(12.5)은 배급이 없어 지닌 것과 수색으로 먹고 산다. 표는 *임시* 값이다: 버려진 곳(구시가·강변·병원·물류창고)이 많이 나오고, 거점은 적게 나온다




### 4.7.1 탐험할 곳 (12-162)

지도에 없는 곳을 찾아 들어간다. 잠입 장면(9.5.1)과 같은 틀이다: 상태와 판정은 코드, 연출은 GM.

- **숨은 곳** (`exploration.ruins`): 구역마다 하나쯤. 그 구역을 뒤지다 수색이 성공하면 찾고, 대가 있는 성공이면 낌새만 준다 (12-220). 찾은 것은 그 캐릭터만 안다 (`ruinsFound`, 원칙 4). 다음 주인공은 다시 찾아야 한다
- **도구** `explore`: `start`(아는 숨은 곳에 들어간다), `deeper`(경계 판정으로 한 칸 내려간다. 마지막 칸은 어렵다), `search`(수색 판정으로 지금 칸을 뒤진다. 칸마다 한 번), `leave`
- **칸마다 찾을 거리 표**: 깊을수록 좋다 (약제실 금고의 모르핀, 무기고의 엽총, 연구동 저온 보관실의 아주 드문 혈청)
- **다침**: 내려가다 실패하면 경상 한 단계 (무너진 천장, 젖은 사다리. 숨은 곳마다 `hazard`)
- **소음** (0~3, 진짜 상태): 대가 있는 성공·실패마다 1. 숫자는 GM도 모르고 낌새로만 (2 이상). 3에 처음 닿으면 깊이에 맞는 감염체(`wake`)가 깊이+1만큼 깨어나 장면에 들어온다 (공포·전투는 기존 규칙). 소리가 났으면 나올 때 판정, 실패하면 나오다 다친다
- `post_apoc` 여섯: 지하철 대피 통로, 옛 병원 지하 약제실, 마트 지하 물류 창고, 발전소 지하 제어실, 교도소 무기고, 의생명 연구동 지하 실험실
- 깨어난 감염체가 장면에 있으면 더 내려가거나 뒤지지 못한다 (싸우거나 빠져나오기만, 플레이 테스트 3)
- 걸음마다 15분. 구역을 옮기면 끝난다. 세이브 `ruinsFound`·`exploration`, 이벤트 `ruin_found`·`exploration_*`. 세이브 형식 62

### 4.8 물건: 무기·탄약·방어구·도구·무게·수리·제작·흥정 (12-38)

물건은 이름과 설명만 있던 것에서, 판정과 몸과 경제에 닿는 것이 된다. 수치는 아이템·시나리오 데이터에 있고 규칙은 core(`engine/gear.ts`)에 있다. GM은 무엇을 쓰는지 고를 뿐, 효과는 코드가 정한다 (원칙 2)

**아이템의 성질** (`items/*.yaml`, 모두 선택)
- `weight`(kg, 없으면 0.5), `value`(흥정 값, 없으면 1), `kind`(무기·방어구·도구·탄약·재료·소모품·음식·기타)
- `weapon { moves, max_harm, noise, ammo?, bonus?, wound?, range? }`: 공격에 쓰는 스킬, 입힐 수 있는 피해 상한(light/heavy), 소음(0 조용함 ~ 2 총소리), 쏠 때 하나씩 쓰는 탄약 아이템, 판정 보정, 스킬별 상처 종류(12-91), 스킬별 사거리(12-93: 거리 → 판정 보정, 없는 거리에서는 칠 수 없다)
- `armor { slot: body|head, reduces, penalty?, blocks_infection? }`: 받는 피해를 줄이는 단계, 입으면 불리해지는 스킬, 물림·긁힘에서 감염을 막을 확률
- `warmth { degrees, when }` (12-98): 체감 기온에 더하는 도. worn: 입고 있을 때 (외투 칸의 방한복), resting: 지니고 자거나 쉴 때 (담요). 방어구 칸에 `outer`(외투)가 있다
- `tool { bonus }`: 지니고 있으면 그 스킬에 보정 (가장 큰 것 하나, 능력+스킬 상한 안)
- `durability`, `breaks_into`: 몇 번 버티는지, 망가지면 남는 것 (부러진 소총 → 고철)
- `repair { move, materials, tools? }`: 고치는 스킬과 재료

**장비** (캐릭터의 `equipped { weapon, body, head }`, GM tool `equip`): 손에 든 무기 하나, 몸과 머리에 입은 방어구. 가진 것만 들고 입는다. 닳은 정도는 캐릭터의 `wear`(아이템별)

**공격** (take_action에서 target_harm을 선언하거나, 전투 중에 근접·사격 판정)
- 손에 든 무기의 스킬이어야 한다. 무기가 없으면 맨손(`gear.unarmed`: 근접, 가벼운 피해까지)
- 무거운 피해(heavy)는 상한이 heavy인 무기로만 노린다
- 탄약을 쓰는 무기는 탄약이 있어야 하고, 쏠 때마다 하나 준다
- 소음: 쏘면 그 구역의 오늘 소음이 오른다 (`noise_made`). 이야기 조건 `zone_noise_gte`로 총소리를 듣고 오는 것들이 열린다
- 무기로 공격하다 실패하면 닳는다 (`durability`만큼 닳으면 망가진다)

**사거리** (12-93): 장면의 인물을 칠 때 GM이 상대와의 거리(`check.distance`: 맞붙음·가까움·멂, `gear.distances`)를 고른다. 무기의 `range`(없으면 `gear.default_range`: 근접은 맞붙음만, 쏘는 것은 가까움까지)에 없는 거리면 칠 수 없고, 있으면 그 보정이 판정에 붙는다 (상한과 따로). 엽총은 맞붙음 +1·멂 불가, 개조 산탄총은 가까움 -1, 소총·석궁은 맞붙음 -1·멂 0, 권총은 멂 -2, 양궁 활은 멂 -1. 산탄총의 판정 보정 +1과 석궁의 -1은 거리 보정으로 옮겼다. 활 (*임시*): 급조한 나무 활(가벼운 피해, -1, 무게 0.5, 목공으로 만든다), 양궁 활(무거운 피해, 무게 1.0, 캠퍼스 양궁부 창고), 화살(목공으로 깎는다). 둘 다 조용하고 찔림. 전투 나이프 (12-94, *임시*): 가벼운 피해까지지만 맞붙으면 +1, 조용하고 가볍고(0.3) 잘 닳지 않는다(10). 지니고만 있어도 생존 +1(도구), 부엌칼 대신 화살·볼트를 깎고 나무 활을 만든다 (제작 도구에 "그중 하나" 목록: `tools: [[kitchen_knife, combat_knife]]`). 상인과 정찰 채비에서 구한다. 깊게 베려면 마체테

**방어**: 주인공이 피해를 받으면 입은 방어구의 `reduces`만큼 단계를 줄이고, 막은 방어구는 닳는다. 감염원에게 다칠 때 입은 방어구마다 `blocks_infection` 확률로 따로 막을 기회를 가진다 (덮는 곳이 달라 겹친다: 1 - Π(1 - p), 가죽 재킷 0.6 + 손목 보호대 0.5 = 0.8). 물림을 막아 낸 방어구도 1 닳는다 (피해를 막지 않고 감염만 막는 가죽 재킷·손목 보호대도 망가질 수 있게). 입은 방어구의 `penalty`(예: 은밀 -1)는 판정에 붙는다

**무게** (`gear.carry`): 들 수 있는 무게 = base + 근력 × per_strength. 넘으면 `encumbered_moves`(은밀·근접 등) 판정에 -1. hard_limit 배를 넘으면 옮겨 가지 못한다 (내려놓아야 움직인다). 넘게 받는 transfer_item은 막는다

**수리와 제작** (take_action의 `craft { recipe | repair }`, 판정 필요)
- 제작 법(`crafting.recipes`): 재료, 필요한 도구, 판정 스킬, 걸리는 시간, 나오는 것. 성공이면 다 나오고, 대가 있는 성공이면 절반(최소 1), 실패하면 재료 절반을 잃는다
- 수리: 성공이면 닳은 것이 없어지고, 대가 있는 성공이면 절반만, 실패하면 재료만 쓴다
- 차량정비·목공 같은 기술 스킬의 쓸모

**값과 흥정** (GM tool `barter`)
- 장면의 인물과 물건을 바꾼다. 받는 쪽 값 × (상인이면 `merchant.markup`) × 관계(신뢰가 높으면 깎아 준다)만큼 줘야 한다
- 넉넉하면 그냥 바꾸고, 조금 모자라면(`barter.haggle_floor` 이상) 교섭·거짓말 판정, 턱없이 모자라면 거절. 값과 판정은 코드가 한다
- 상인(NPC의 `merchant { restock, markup }`)은 날마다 모자란 만큼 다시 채운다

**무기고** (12-39, 플레이 피드백: 부엌칼만 들고 작전에 나갔다)
- 무리의 `armory { items, ammo_cost }`: 무장이 필요한 작전(임무의 `armed`)을 받으면 무기·탄약을 빌려주고 받은 총을 손에 든다. 이미 쏠 수 있는 총이 있으면 총은 빼고 모자란 탄약만
- 빌려줄 때마다 무리 창고의 탄약이 `ammo_cost`만큼 준다. 창고가 모자라면 탄약 없이 무기만 (전황이 장비에 닿는다)
- 임무가 끝나면(보고·포기) 거둬들인다. 탄약은 쓰라고 준 것이고, 무기를 잃어버렸으면 공적 -1. GM 상태의 "복무·임무"에 빌린 것이 보인다
- `post_apoc`: 청솔 낡은 소총 + 소총탄 둘, 버들마을 엽총 + 산탄 둘, 붉은연합 개조 산탄총 + 산탄 둘, 여울섬 소총 + 소총탄 넷. 하얀매(중립 진료소)와 나루상단(각자 갖춘다)은 없다. 정찰·보초·호위·습격·수색 같은 작전 37개가 `armed`

**급조와 손질** (12-40): 스킬 둘을 더했다 (16 → 18)
- 급조(`improvise`, 지능·민첩): 아무거나 엮어 무기·방어구·덫을 만들고 고친다. 목공은 판자·담장·바리케이드 쪽으로 좁혔다. 사제 창·덧댄 갑옷·못 박은 방망이·철사 덫을 급조로 옮기고, 화염병·손목 보호대·깡통 경보줄·배낭 틀을 더했다. 방어구·석궁·방망이 수리도 급조
- 손질(`maintenance`, 지능·감각): 총·칼을 고치고, 닳지 않게 다룬다. `gear.maintenance.save_chance`: 손질 0·1·2일 때 닳음을 피할 확률 (15·35·55%)
- 아이템의 `carry_bonus`(배낭 틀 +6kg, 가장 큰 것 하나), 방어구 자리 `arms`(팔: 손목 보호대)
- 인물 열 명이 새 스킬을 가진다 (재생탄 장수 강은숙·여울섬 진강호 손질 2, 떠돌이 반석구·폭약을 다루는 박만수 급조 2 등)

**구현 메모**
- 탄약은 무기의 `ammo_moves`(없으면 무기의 스킬 전부)로 쏠 때만 쓴다. 소총은 쏠 때만 탄약·총소리, 개머리판은 조용하다
- 처음 시작할 때와 다음 캐릭터로 이어 갈 때 가진 무기 중 가장 센 것을 손에 든다 (탄약이 있는 총 먼저)
- 방어구가 피해를 다 막으면 피해 기록 없이 "다치지 않았다"
- 판정 보정에 `gear`(방어구·짐의 불리함)가 따로 붙고, 무기·도구의 보정은 능력+스킬 상한 안에 든다
- 이야기 조건 `zone_noise_gte`는 그 구역의 오늘(1일차부터 세는 날) 소음

**콘텐츠 (`post_apoc`)**

#### 4.8.3 거점 손보기 (12-167)

떠돌이의 거처(4.8.1)와 무리의 거점을 주인공이 손으로 고친다. 시설은 구역에 붙는다 (`facilities`, 세이브 형식 65).

**정한 것** (2026-11-18)

- 거처와 무리 거점을 한 번에 한다
- 무리 거점에도 **누구나 지을 수 있다** (허락 없음). 지으면 성실함 행적이 남아 무리의 평판에 닿는다
- **시간으로는 닳지 않는다.** 그 구역에 습격·공격(교전)이 오면 시설 하나가 부서진다 (담이면 담도 헐린다). 큰 재난(9.18)이 생기면 같은 길로 부순다. 내 거처·우리 땅이면 소식으로 듣는다

- 거점의 큰 시설(방벽, 감시탑)은 무리 단위라 회의 방침과 엮어야 해서 넣지 않았다

#### 4.8.4 가축 (12-175)

거처·거점에서 짐승을 친다. 새 규칙은 없고 시설(4.8.3)의 한 종류다. 텃밭의 "자라는 것"(`garden`)을 그대로 쓰되 계절을 가리지 않는다.

**정한 것** (2026-11-18, 권장안으로 진행)

- 짐승은 **산 아이템**으로 얻는다 (시세·수색·이야기). 우리를 지을 때 재료로 들어간다
- 먹이는 따로 세지 않는다. 짐승이 있는 곳의 위험은 **이야기**로 온다 (밤에 닭장을 노리는 것, 우는 염소가 부르는 것)
- 부서지는 길은 시설과 같다 (습격·공격·재난). 부서지면 짐승도 잃는다

| 시설 | 어디 | 판정·시간 | 재료 | 효과 |
|---|---|---|---|---|
| 닭장 | 거처·거점 | 목공 3시간 | 판자 2·철사·산 닭 2 | 거처면 이틀마다 달걀 2개가 창고에, 거점이면 날마다 무리 식량 +1 |
| 염소 우리 | 거처·거점 | 목공 4시간 | 판자 3·밧줄·염소 | 거처면 날마다 염소젖 하나가 창고에 (상한다), 거점이면 날마다 무리 식량 +1 |

- 이야기 조건 `facility_here: <시설 id>` (지금 구역에 그 시설이 있다). `post_apoc` 이야기 셋 (`storylets/livestock.yaml`): 닭장을 노리는 그림자(밤), 우는 염소(감염체 낌새), 달걀을 훔친 아이
- 얻는 곳: 나루상단 장터의 탁봉수(산 닭은 늘, 염소는 가끔 `rare`), 길 위의 일 "길 잃은 염소"
- 아이템 (`items/livestock.yaml`): 산 닭·염소(재료), 달걀(조금 상한다)·염소젖(빨리 상한다)

#### 4.8.2 시세 (12-155, 교역망 1단계)

물건 값이 고정이라 어느 무리 창고가 비어도, 겨울이 와도 값이 같았다. 그 땅 주인 무리의 창고 형편과 계절을 값에 곱한다. 규칙은 core `engine/market.ts`, 수치는 월드의 `market` (*임시*)

- **어느 자원을 따르나**: 아이템의 `resource`, 없으면 종류(`market.kinds`: 음식 → 식량, 탄약 → 탄약). `post_apoc`은 약(구급상자·붕대·항생제·해열제) → 의약품, 물병 → 물, 땔감·기름병 → 연료, 화약·탄피 → 탄약. 담배·혈청처럼 이어지지 않은 물건은 그대로다
- **배수**: 그 땅 주인 무리의 창고가 처음보다 얼마나 남았는지. 처음의 25% 이하면 1.5배, 처음과 같으면 1배, 두 배 이상이면 0.7배 (사이는 곧게 잇는다). 비율로 재서 날마다 쓰지 않는 자원(탄약·의약품)도 같은 틀이다. 계절 배수를 곱한다 (겨울 연료 1.4, 여름 물 1.2)
- **쓰는 곳**: 흥정(`barter`)의 주고받는 양쪽 값, 뇌물(`bribe`)의 값. 그래서 넉넉한 곳에서 사서 모자란 곳에 파는 장사가 저절로 생긴다. 주인 없는 땅에는 시세가 없다
- **보이는 곳**: 주인 있는 땅의 거점이나 말이 모이는 곳(9.13)에서 GM 상태에 "시세: 식량이 비싸다, 탄약이 싸다" (1.2배 이상·0.85배 이하만, 숫자 없이)
- 세이브 형식은 그대로다

**교역망 2·3단계 (설계, 아직 하지 않음)**
- 2단계 나루상단 짐수레: 정해진 길(장터 → 정수장 → 휴게소 → 버들마을 …)을 며칠마다 돈다 (하루 틱에 한 구역). 교역 방침(9.11)은 짐수레가 그 무리 땅에 닿을 때만 바뀐다 (지금은 날마다 자동). 길이 위험하면(감염체 압력, 교전) 늦거나 털리고, 털리면 그 무리 교역이 끊기고 시세가 뛴다. 주인공은 호위(임무)·습격(행적·현상금)·짐꾼(나루상단 짐꾼 시나리오)으로 낀다. 세이브 상태 하나(짐수레 위치·짐), `war:sim`으로 균형을 다시 본다
- 3단계 AI 무리의 교역: AI 무리가 모자란 자원을 보고 교역 방침을 스스로 고른다. 전쟁 균형이 크게 흔들려 권하지 않는다
- 넣지 않는 것: 따로 된 화폐(담배가 사실상의 돈), 주인공의 가게·장부 관리(분배표를 뺀 것과 같은 이유, 15.2)

#### 4.8.1 내 물건 보관: 사물함과 거처 (12-149)

무게 제한(4.8) 때문에 다 들고 다닐 수 없는 물건을 맡겨 둔다. 규칙은 core `engine/stash.ts`

- **어디에**: 무리에 들었으면 우리 무리 거점의 사물함(숙소·막사), 떠돌이면 스스로 정한 거처 한 곳. 거처는 다른 무리의 거점과 외딴곳(`isolated`)이 아니면 어디든 정할 수 있다 (`stash` settle). 무리에 든 사람은 거처를 정하지 않는다
- **용량 제한 없음**. 게임 시간을 쓰지 않는다 (줍고 내려놓기와 같다). 걸친 것은 먼저 벗어야 맡긴다. 꺼낼 때도 들 수 있는 무게(hard_limit)를 넘으면 덜 꺼낸다
- **맡긴 물건은 그 구역에 남는다**: 거처를 옮기거나 무리를 옮겨도 예전 자리의 물건은 거기 있다. 넣기는 지금 자리에만, 꺼내기는 그 구역에 가면 된다. 세이브 `stashes`(캐릭터 → 구역 → 물건), `homes`, 이벤트 `item_stashed`·`home_settled`. 세이브 형식 56
- **MCP 모드**: 채팅으로 한다. GM이 `stash` tool(put·take·settle)을 부른다. GM 상태의 "창고" 줄에 지금 넣을 수 있는 자리와 맡겨 둔 것, 떠돌이의 거처. `?소지품`에도 나온다
- **무게 안내**: 소지품 무게가 한도를 처음 넘으면 그 tool 결과에 창고 안내를 한 번 붙인다 (캐릭터마다 한 번, `stashHinted`)
- **상태 화면**: 내가 사물함·거처에 있을 때만 아이템 탭의 소지품 아래 "창고" 영역과 옮기기 버튼이 보인다. 소지품마다 넣기 아이콘(아래 화살표와 받침), 창고 물건마다 꺼내기 아이콘(위 화살표와 받침). 누르면 하나, 누르고 있으면 0.5초 뒤부터 0.1초마다 하나씩 (`POST /api/stash`, core `GameWorld.moveStash`). 예전 자리에 맡긴 것은 채팅으로 꺼낸다
- 넣지 않은 것: 털리는 창고(도둑·습격), 다른 사람과 같이 쓰는 창고, 계승한 다음 캐릭터가 전 주인공의 창고를 여는 일
