# 인물의 장소가 null인 것, 그리고 "구역 밖" 일과 칸 (계획)

2026-11-23. 공통 규칙 15(장소) 후속. **A안은 장소 개편(12-274)과 함께 구현했다. null은 장소가 하나도 없는 구역에서만 남는다.** 설계 목록 9-7(`docs/playtests/design-queue.md`)과 12-270·12-272에서 남긴 빈틈을 한데 모았다.
코드 위치는 커밋 `580620b`(12-272) 기준이다. 같은 시각 다른 세션이 `rules/place.ts`에 잠입 깊이(B③ `depthAt`)를 더하고 있어 줄 번호가 조금 밀릴 수 있다.

## 0. 요약

- `whereIs`의 `place: null`은 지금 **세 뜻**을 겸한다: ① 장소를 모름(구역 어딘가), ② 막 들어선 자리, ③ 구역에 없어야 하는데 구역에 있음(일과가 "구역 밖" 말인 칸).
- ③이 가장 크다. 실제 콘텐츠에서 이름 있는 인물 37명의 49칸, 낮에는 30명이 "털이·정찰·길 위"인데 엔진은 그 사람을 제 구역 어딘가에 둔다. 그래서 숨은 목격자로 굴리고, GM이 경고 없이 들이고, 이야기 배역과 구역 치료사에 끼고, 상관이면 "거점 어딘가"로 나온다.
- 권장: **A안(일과가 구역 밖 말이면 그 시간대엔 구역에 없다)만 지금 한다.** 상태·이벤트·세이브 형식은 그대로, `rules/place.ts`에 15줄 안팎. 다른 구역을 말하는 칸(B안)과 null 두 뜻 가르기(C안)는 플레이 테스트에 두 번 나올 때까지 backlog.

## 2. 실제 데이터 규모 (post_apoc, 스크립트로 셈)

임시 스크립트(scratchpad, 프로젝트에 남기지 않음)로 `loadContent` + `placeSaid` + `routine_away`를 그대로 써서 셌다.

- 이름 있는 인물 131명, 떠도는 인물 6명, 구역 21곳 모두 장소가 있다(경우 8은 실제 콘텐츠에 없음).
- 떠돌지 않는 인물의 일과 칸 625칸 중 빈 칸 82(새벽 36, 아침 27, 저녁 18, 낮 1). 빈 칸은 앞 시간대 말을 이어 쓴다.
- `routine_away`로만 통과한 칸: **49칸, 37명**. 말별: 길 위 10, 들어가기 7, 털이 6, 나가기 6, 호위 4, 정찰 4, 수색 3, 다녀오기 3, 왕복 2, 심부름 2, 오가기 1, 연락 1, 따라가기 1.
- 일과로 정해지지 않는 말이 남은 칸(경우 10 중 말이 있는데 안 맞는 것): 0 (12-270 검사).

## 4. 선택지

각 안마다 늘어나는 것을 먼저 적는다.

### A안. 일과 칸이 구역 밖 말이면 그 시간대엔 구역에 없다 (규칙, 권장)

| 늘어나는 것 | 양 |
|---|---|
| 상태 필드 | 없음 |
| 이벤트 | 없음 |
| 세이브 형식 | 그대로 (계산만 바뀐다. `SAVE_SCHEMA_VERSION` 올리지 않음) |
| 콘텐츠 | 없음 (`routine_away` 목록을 그대로 씀) |
| 규칙 줄 | `rules/place.ts` 15줄 안팎 + `tools.ts` 경고 3줄 + `reputationTools.ts` 1줄 |

- 판정: 떠돌지 않는 인물의 그 시간대 일과 말(빈 칸은 앞 시간대)이 제 구역 장소로 정해지지 않고 `routine_away` 말을 가지면 "나가 있음". 거처(밤의 주인 있는 즉흥 장소)가 있으면 거처가 먼저.
- `whereIs`는 `{ zone: null, place: null }`을 돌려준다 (길 위). 갇힘·장면·동행·머무는 자리·기다림·분대 일이 먼저다(지금 순서 그대로, 일과 바로 앞).
- 대부분의 소비자는 zone null을 "여기 없음"으로 이미 읽는다: `inZone`·`nearby`·`peopleAt`·`hereWithMe` 거짓, 배역 `here`·구역 낯선 사람·구역 치료사에서 빠짐.
- 손볼 곳 셋:
  1. `sharesPlace`: zone이 null이면 거짓 (지금은 장소 null이면 참).
  2. 숨은 목격자(`reputationTools.ts:190~191`): 지금은 `zoneOf`가 null이면 "모르는 사람이라 굴린다". 나가 있는 사람은 `sharesPlace`에서 걸러지므로 1로 충분하다(확인만).
  3. `whereLabel`: 나가 있으면 "나가 있다 (털이)"처럼 일과 말을 붙인다. 상관 오류 글과 npc_presence 경고가 이것을 쓴다.
- npc_presence: **막지 않고 알린다.** "이 사람은 보통 지금 나가 있다(구시가·강변 털이): 돌아온 까닭을 서술하라". 분대 일(경우 6)은 막지만, 일과는 GM이 이야기로 바꿀 수 있는 기본값이라 경고로 둔다.
- `zoneOf`는 그대로 둔다(유해·변이 자리). whereIs가 zone null을 돌려주면 `zoneOf`도 null이 되니, 유해 자리처럼 구역이 꼭 필요한 곳(`turning.ts`·`remains.ts`)은 죽은 사람이라 whereIs가 null이고 일과 구역으로 내려간다. 산 사람의 구역을 쓰는 `seatStartSquad`만 확인.

### B안. 일과 칸에 다른 구역을 데이터로 적는다

| 늘어나는 것 | 양 |
|---|---|
| 상태 필드 | 없음 |
| 이벤트 | 없음 |
| 세이브 형식 | 그대로 |
| 콘텐츠 스키마 | NPC에 선택 필드 하나: `routine_zone: { evening: a_base, night: a_base }` (시간대 → 구역) |
| 콘텐츠 | (다) 19칸 + (나) 중 한 구역인 2칸에 `routine_zone`. 일과 글을 그 구역 장소 별칭에 맞게 손봄 ("거점 식당" → "식당 천막") |
| 검사 | `checkNpcRoutines`: `routine_zone`의 칸은 그 구역 장소로 정해져야 한다, 떠도는 인물과 함께 쓰지 않는다. "들어가기·다녀오기·나가기"를 `routine_away`에서 뺌 |
| 규칙 줄 | `npcZoneAt`에 시간대 인자 3~5줄, `npcPlaceAt`가 그 구역으로 찾도록 1줄 |

- 글자로 다른 구역을 찾는 규칙(설계 목록 9-7의 원래 안)은 2.2대로 19칸 중 9칸이 틀리거나 겹친다. 그래서 데이터 필드다.
- 효과: 남쪽 텃밭 경비 셋이 낮에 남쪽 밭에, 라젠드라가 저녁 식당 천막에, 함영자가 밤 103동에 있다. 그 자리의 숨은 목격자·장소 목록·배역에 든다.
- 원칙 7(장르 하드코딩 금지)에 걸리지 않는다: 구역 id는 콘텐츠 데이터다.
- A안 없이 B안만 하면 (가)·(나) 30칸(낮의 대부분)은 그대로 샌다. B안은 A안 다음 단계다.

### C안. null의 두 뜻 가르기 (막 들어선 자리와 모름)

| 늘어나는 것 | 양 |
|---|---|
| 상태 필드 | 없음 (세이브의 null은 그대로 "막 들어선 자리"로 읽는다) |
| 이벤트 | 없음 |
| 세이브 형식 | 그대로. 세이브에 `"entry"` 같은 표시를 쓰는 길(C-2)은 `playerPlace`·`npcStays`·`apart`·`place_moved` 뜻이 바뀌어 `SAVE_SCHEMA_VERSION` 96, 권하지 않음 |
| 규칙 줄 | `whereIs` 반환에 `fixed`(장소를 안다, 막 들어선 자리 포함) 하나, `sharesPlace`·`hereWithMe` 각 1줄. 10줄 안팎 |

- `fixed`가 참인 것: 주인공, 장면·동행(주인공 자리), `npcStays`, `apart`, 가두는 장소. 거짓: 분대 일, 엑스트라, 일과로 못 정한 사람.
- `sharesPlace`: fixed면 `place === playerPlace` (막 들어선 자리끼리 참, 막 들어선 자리에 둔 사람은 막사 안 일을 못 봄). `hereWithMe`: fixed면 null끼리도 참 (막 들어선 자리로 돌아오면 두고 온 사람이 저절로 들어옴).
- 근거가 약하다: 막 들어선 자리에 사람을 두고 떠난 뒤 그 구역 다른 장소에서 일을 벌이는 경우만 해당하고, 플레이 테스트 보고는 없다. B③(잠입 깊이)이 주인공의 null을 "깊이 0"으로 쓰기 시작해 뜻 ②가 더 굳어지는 것은 맞다.

### D안. 일과 칸을 모두 제 구역 장소로 고친다 (콘텐츠만)

| 늘어나는 것 | 양 |
|---|---|
| 규칙·상태 | 없음 |
| 콘텐츠 | 49칸 글을 고치고 `routine_away` 목록을 지움 |

- "털이"를 "창고 마당에서 털이 준비"로 고치면 누수는 없어지지만 세계가 거짓말을 한다: 털이조·상단·정찰조가 낮 내내 거점에 있다. 이야기(털이 나간 사이 거점이 빔)와 어긋난다. 권하지 않는다.

### 데이터로 고치기와 규칙으로 고치기

| | 규칙 (A) | 데이터 (B·D) |
|---|---|---|
| 콘텐츠 작가가 할 일 | 없음. 일과를 사람 말로 쓰면 됨 | 칸마다 구역을 적음 (B) / 글을 엔진에 맞춤 (D) |
| 틀릴 곳 | `routine_away` 말이 장소 이름과 겹치면 장소가 이김(지금도 `placeSaid`가 먼저) | 적지 않으면 조용히 제 구역 (검사로 막음) |

| 표현할 수 있는 것 | "구역에 없음"까지 | "다른 구역의 그 장소"까지 |

둘은 겹치지 않고 이어진다. A는 "없음", B는 "저기 있음"이다.

## 7. 권장안

1. **A안만 지금.** 일과가 구역 밖 말이면 그 시간대엔 `whereIs` zone null(길 위). `sharesPlace`가 zone null이면 거짓, `whereLabel`은 "나가 있다(일과 말)", npc_presence는 막지 않고 알린다. 주인공의 분대원은 뺀다.
2. 상태·이벤트·세이브 형식 그대로, 콘텐츠 그대로, 규칙 20줄 안팎. 테스트: 실제 콘텐츠로 "낮 붉은연합 거점에서 털이조는 숨은 목격자가 아니다", "주인공 분대원은 낮에도 거점에", "나가 있는 상관 오류 글".
3. (다) 19칸은 A안으로 "나가 있음"이 된다. 라젠드라가 저녁 식당 천막 대신 길 위에 있는 것은 틀렸지만 누수는 없다. B안(`routine_zone`)은 다른 구역의 그 자리에 사람이 없다는 보고가 두 판에서 나오면.
4. C안은 backlog. 막 들어선 자리에 두고 온 사람의 목격 보고가 나오면 `fixed` 하나로.
5. D안은 하지 않는다.

## 8. 정해야 할 것

1. A안을 할까? npc_presence는 경고(권장)로 할까, 분대 일처럼 막을까?
2. 주인공의 분대원은 일과가 구역 밖이어도 구역에 둘까(권장: 둔다)? 주인공의 상관도 뺄까(권장: 빼지 않는다. 임무는 새벽·아침에 받고 저녁에 보고)?
