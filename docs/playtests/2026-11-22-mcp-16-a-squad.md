## 1. 요약

1. **[버그] 인자 오류에 도구 인자 모양이 붙지 않는다 (12-260이 MCP에서 죽어 있다).** MCP SDK가 `registerTool`의 `inputSchema`로 먼저 검증해 `MCP error -32602: Input validation error ...`로 끝나고, core `executeTool`의 `argsHint`까지 가지 못한다 (o1 take_action·npc_presence, o5 squad_order, o6 `check.harm_cause` null, o39 deed). 이번 판에서 인자 오류로 버린 호출이 6번.
2. **[버그] 설정 거스르기에 실패해 "그 행동은 일어나지 않았다"인데, 같은 턴의 `resolve_storylet defy`가 그대로 풀렸다.** 규율 회의에서 복종을 거스르는 굴림이 실패(`🎲 버티기 · 복종을 거스른다 ... = 4 · 실패`)했는데 바로 뒤 "대든다"가 적용돼 공적 -2·신뢰 하락 (o42). 꺾인 행동에 걸린 선택지는 거절해야 한다.
3. **[버그] 치료사가 같은 장소에 있는데 `treatment {item: null}`이 "수술을 배우지 않아 손댈 수 없다"로 끝난다.** 의무실(윤채원·허세린이 "지금 여기")에서 치명상 치료를 부르자 주인공 혼자 하는 치료로 보고 거절했고, 12-256의 "이 구역의 수술할 줄 아는 사람을 알린다"도 나오지 않았다 (o32). npc_presence로 둘을 들이자 윤채원이 수술감으로 골려 제대로 됐다 (o33).
4. **[균형] 분대 전원을 with로 넣어도 감염체 하나에 무너진다.** 분대원 셋을 with에 넣고 빠른 감염체를 쳤는데 `+1(임동욱이 도움) -1(경상) -2(상대가 근접전에 능함) -1(감염체 3) = 4 · 실패`. 이어 후퇴(운동) 실패로 주인공 치명상, 왕기범 중상, 임동욱 경상 (o29~o31). 총 든 저격수 권예진을 포함한 여섯이 감염체 셋에 손을 못 쓴다. 그런데 치명상은 36시간 만에 다 나았다 (o61).
5. **[설계] 같은 무리 창고를 터는 길이 막혀 있다 + 도둑맞은 사람의 신뢰가 오른다.** 우리 거점 보급 창고를 search로 뒤지자 `-1(털린 구역)`이 붙어 실패, 빈손 (o39). 상자와 자루가 줄지어 있다는 창고가 구역 수색표로 "털린 곳"이다. 주머니를 털다 들킨 차연희는 신뢰가 오히려 +1 (o59, 정직 -2 가치관 때문으로 보임).

### [버그]

1. **인자 오류에 인자 모양이 붙지 않는다 (12-260 `argsHint`).** `packages/mcp/src/server.ts`가 core 스키마를 `inputSchema`로 등록해 SDK가 먼저 거른다. 결과는 `MCP error -32602: Input validation error: Invalid arguments for tool take_action: Invalid input: expected object, received string at activity` 같은 zod 문구뿐이다 (o1, o5, o6, o39). core의 `executeTool` 안 argsHint는 단위 테스트에서만 보인다.
   - 고칠 안: MCP에는 느슨한 스키마(`z.object({}).passthrough()` 등)를 등록하고 검증은 core에서만 하거나, SDK 오류를 잡아 core의 `argsHint`를 붙여 돌려준다. MCP 수준 테스트를 하나 둔다 (틀린 인자로 callTool → 결과에 "이 도구(...)의 인자:")

   - 고칠 안: 판정이 붙은 선택지가 "이번 턴 take_action의 판정"을 요구하듯, 이번 턴 take_action이 `against_setting`에 꺾였으면 resolve_storylet을 거절한다 ("이 행동은 일어나지 않았다. 다른 선택지를 고르거나 다시 하라")

### [균형]

1. **with 도움이 사람 수와 상관없이 +1 하나.** 분대원 셋을 with에 넣어도 `+1(임동욱이 도움)` (o30). 감염체 쪽은 `-2(상대가 근접전에 능함)` `-1(감염체 3)`이라, 여섯이 셋을 상대하는 장면이 주인공 혼자 싸우는 것보다 조금 나을 뿐이다. 총을 든 권예진·왕기범은 쏘지 않는다.
   - 고칠 안: 숫자의 우위를 장면의 편 인원으로 상쇄한다(`감염체 3`과 `우리 6`). 또는 "분대가 함께 맞선다"를 `squad_order`의 전투 일로 두어 분대원도 굴리게 한다
2. **"막아서다"가 있어도 주인공도 다친다.** o29·o30·o31: `한 단계 더. 왕기범이 막아서다 대신 다쳤다. ... 도윤의 부상: 경상 → 중상`. "대신"이라는데 주인공도 한 단계를 그대로 받는다. 더해진 한 단계만 막아선 것이라면 문구가 오해를 부른다.
   - 고칠 안: "더해진 한 단계는 왕기범이 막아서다 대신 받았다"처럼 몫을 밝힌다
3. **회복이 빠르다.** 1일차 15:28 치명상 → 수술 → 중상, 그날 밤 잠으로 경상. 2일차 11:20 총상으로 다시 중상 → 치료 경상 → 3일차 04:00 "이상 없음" (o37, o58, o61). 치명상에서 이틀이 안 돼 멀쩡하다.
4. **우리 거점 보급 창고가 "털린 구역".** o39: `🎲 수색: +1(감각) -1(수색) -1(경상) -1(털린 구역) +3(주사위)`. 무리 창고 도둑질은 search + 수색 판정(12-258)인데, 구역 수색표를 그대로 써서 창고가 털린 폐허처럼 굴린다. 같은 날 구시가에는 `+1(뒤질 거리가 많은 구역)`.
   - 고칠 안: 우리 무리 창고 장소(storehouse 등)를 뒤지면 무리의 재고에서 꺼내는 표로 굴린다 (꺼낸 만큼 무리 창고에서 빠짐)
5. **분대장인데 2인 1조 짝이 붙는다.** o50: `짝: 강태호(a_taeho)가 이 임무 동안 함께 다닌다 (2인 1조)`. 강태호는 다른 분대의 분대장이다. 분대 넷과 신병 하나를 데리고 나가는데 남의 분대장이 따라붙었다.
   - 고칠 안: 분대를 맡은 사람에게는 짝을 붙이지 않는다 (또는 분대원 하나로)

### [설계]

1. **도둑맞은 사람의 신뢰가 오른다.** 차연희 주머니를 털다 들켰는데 `?인물 차연희` → `신뢰 보통 +1` (o59). 행적 반응이 가치관(정직 -2)만 보고 피해자인지를 보지 않는 듯하다.
   - 고칠 안: 행적의 대상(target)이 본 사람이면 가치관과 상관없이 신뢰·호감을 내린다 (공통 규칙 13 `hurtResentment`와 비슷하게)
2. **규율 회의로 옮겨 갔다는 줄이 없다.** o41: 보급 창고에서 회의가 열렸고 "지금 있는 곳: 교무실"로 바뀌어 있었지만, 결과에 "교무실로 불려 갔다" 같은 줄이 없다. 장면 정보를 다 읽어야 장소가 바뀐 걸 안다. 차연희(본 사람)는 창고에 남았다.
   - 고칠 안: summons로 옮길 때 "○○로 불려 갔다 (장면의 사람 남음, 동행 함께)" 한 줄
3. **"방금 빗나간 상대"가 내 분대원에게도 붙는다.** o47: 훈련(통솔)에서 시범을 보이는 임동욱을 target으로 두자 `-1(방금 빗나간 상대)`. 12-258은 설득·속임처럼 맞서는 상대를 생각한 것인데, 도와주는 사람이 "상대"로 셌다.
   - 고칠 안: 같은 무리이고 맞서지 않는 target에는 붙이지 않거나, opponent일 때만
4. **분대 수색 전리품이 짐 한도를 넘겨도 그냥 들어온다.** o57: 텃밭 수색 넷을 받자 `짐 11.7/12kg`. 한도를 넘었으면 사물함에 넣는 12-259의 `stowStartingLoad` 같은 처리가 있으면 좋겠다 (이번엔 넘지는 않았다).
5. **assign_mission이 같은 장소의 상관을 들이지 않는다.** o4: 막사에 한태경이 있는데 `assign_mission` → `먼저 npc_presence로 등장시키세요`. 12-253의 `hereWithMe`는 인자에 id가 있어야 해서 상관 id가 없는 assign_mission·report_mission은 늘 한 번 더 부른다. 상관이 다른 데 있으면 어디 있는지도 오류에 없다 (o48, o49에서 get_scene으로 찾음).
   - 고칠 안: 상관이 같은 장소면 들이고, 아니면 오류에 "지금 ○○"을 붙인다

### [이야기 전제]

1. **강가에서 열린 "총소리를 듣고 온 것들"이 골목을 말한다.** o28: 강가(bank)에서 `골목 끝 그늘에서 무언가 몸을 일으킨다`, 배역 이름도 "골목 끝의 감염체". 강가는 갈대와 자갈이다.
2. **"처음 듣는 총소리"의 앞 이야기 플래그가 판정에 안 닿는다.** o51: `앞서 굴렸다면(os_rookie_drilled) 소리를 지르면 몸이 먼저 반응한다`. 1일차에 혹독하게 굴렸는데(o24) 고함은 위협 3 실패, 신병과 주인공 둘 다 총상 (o52). GM이 난이도를 easy로 내렸어야 했지만, 글만으로는 GM이 놓치기 쉽다.
   - 고칠 안: 선택지 판정에 플래그 보정을 데이터로 둔다 (`check_bonus_if: os_rookie_drilled`)
3. **표지판 낙서 믿음이 틀린 채 남는다.** o6: 경계 실패 → `알게 된 것: 버들마을 거점 근처 표지판 낙서에 이 길이 안전하다고 적혀 있었다` ([소문]). 의도된 거짓 정보로 보이며 문제는 아니지만, 믿음 목록에 "소문"으로만 남아 틀린 것인지 플레이어가 알 길은 없다.

### [정보 누설]

1. **id에 원래 이름이 남는다.** GM 상태에 줄곧 `상관 한태경(a_doyun)`. 주인공 이름이 "도윤"이라 GM이 id만 보고 헷갈리거나, 원래 이름을 짐작할 수 있다. 플레이어에게 보이는 글은 아니다.

### [GM 부담]

1. **deed 모양이 GM 안내의 "자주 쓰는 인자"에 없다.** o39: `type`·`description`으로 넣었다가 `summary, tags, severity, privacy, noisy, condition`이 필요하다는 오류. 도둑질은 GM 안내가 직접 권하는 일인데 인자 모양을 오류로 배웠다.
2. **`check.harm_cause`에 null을 못 넣는다.** o6: 위험이 none이라 `harm_cause: null`로 냈더니 오류. 12-252는 "위험이 none이면 생략"인데 안내의 check 모양에는 `harm_cause`가 있다. 빼도 된다는 표시(?)나 null 허용이 필요하다.
3. **통솔에 지능을 못 쓴다는 것을 오류로 배웠다.** o45: `leadership에는 charm 또는 nerve 능력치만 쓸 수 있습니다`. 스킬마다 쓸 수 있는 능력이 상태에 보이면 좋다.
4. **실행 횟수가 목표의 두 배.** 인자 오류(6회), "장면에 없다" 오류(assign·report·target 4회)로 다시 돌린 것이 컸다.

## 6. 좋았던 것

- 이름 대체가 깔끔했다. 주인공 "도윤"과 상관이 한 번도 겹치지 않았고, 콘텐츠 곳곳(믿음, 남의 평판)까지 바뀌었다
- 분대장 판의 흐름이 살아 있었다. 신병을 맡고(맡겨진 사람) → 다음 날 그 신병이 총소리에 굳는 이야기(처음 듣는 총소리)로 이어졌다
- 총 한 발이 감염체 물결을 부르는 연결(사격 → "총소리가 멀리 퍼졌다" → 이야기)이 자연스러웠다
- 지혈이 "위협이 가시면"으로 바뀌어 후퇴 장면이 그럴듯했다. 거점에 닿는 순간 신병이 분대장의 피를 막았다
- 규율 회의가 도둑질 직후 교무실로 불러 가는 흐름이 빠르고 무리 문화(실망한 한태경)에 맞았다
- 분대 수색조가 돌아와 전리품을 건네는 것, 사물함을 의무실에서도 쓸 수 있는 것이 손이 덜 갔다
- 감염이 하루 뒤 "몸살 기운"으로 드러나 1일차의 할큄이 무게를 가졌다
