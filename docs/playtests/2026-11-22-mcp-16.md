## 1. 요약

1. **[버그] 12-260의 인자 오류 안내(`argsHint`)가 MCP에서는 한 번도 붙지 않는다 (네 판 모두).** `packages/mcp/src/server.ts`가 core 스키마를 `inputSchema`로 등록해 MCP SDK가 먼저 `-32602 Input validation error`로 거절한다. core `executeTool`까지 가지 못한다. 단위 테스트는 core를 직접 불러서 놓쳤다.
2. **[버그] 장소를 옮기는 턴에 도착지의 사람을 target으로 넣으면 "장면에 없다" (분대장·졸병·섬, 세 판).** 12-253의 들이기(`hereWithMe`)가 옮기기 전 장소를 본다. assign·report·treatment처럼 인자에 id가 없는 도구도 같은 장소의 상관·치료사를 들이지 않는다 (분대장·섬).

## 3. 두 판 이상에서 겹친 것

### 3-1. [버그] 인자 오류 안내가 MCP에서 안 붙는다 (네 판)
- 분대장 o1·o5·o6·o39(6회), 졸병 o1·o2·o7·o9(4회), 섬 o1(1회), 튜토리얼 o24(1회). 모두 `MCP error -32602: Input validation error ... Unrecognized key ...`만 나오고 "이 도구(…)의 인자:" 줄이 없다
- 원인: `packages/mcp/src/server.ts`의 registerTool이 `inputSchema: tool.schema`로 등록 → SDK가 먼저 검증
- 고칠 안: MCP에는 느슨한 스키마를 등록하고 검증은 core에만 둔다. 또는 SDK 검증 오류를 잡아 core의 `argsHint`를 붙인다. MCP 클라이언트로 틀린 인자를 보내는 테스트를 둔다

### 3-2. [버그·GM 부담] 같은 장소의 사람을 들이지 못하는 경로 (분대장·졸병·섬)
- **place_to + target 한 턴**
  - 분대장 o10: place_to barracks + target a_doyun
  - 졸병 o5: barracks + a_taeho, o9: storehouse + a_haneul
  - 섬 o21: dock + y_gangho
  - 모두 "장면에 없습니다". 고칠 안: place_to가 있으면 옮긴 뒤 장소로 들인다
- **assign_mission·report_mission이 같은 장소의 상관을 들이지 않는다**
  - 분대장 o4, 섬 o16: "먼저 npc_presence로 등장시키세요"
  - 상관이 다른 데 있으면 어디 있는지도 오류에 없다 (분대장 o48·o49)
  - 고칠 안: 상관이 같은 장소면 들이고, 아니면 "지금 ○○"을 오류에 붙인다
- **treatment가 같은 장소의 치료사를 찾지 않는다** (분대장 o32, 4절)

- **[균형] 8kg 한도에 수색 한 번(땔감 ×2)으로 12.7kg "옮겨 가지 못한다"** (o28)

- **[설계] 거절당한 방문자가 거점 안 장소로 막힘 없이 들어간다** (o14). 정문 장소 이름 "운동장·정문·담장"도 담 안팎을 섞는다

## 6. 좋았던 것 (판마다 원문 6절)

- 이름 대체가 깔끔했다. 콘텐츠 곳곳(믿음, 남의 평판)까지 바뀌었다 (분대장)
- 신병을 맡고 → 다음 날 그 신병이 총소리에 굳는 이야기, 총 한 발이 감염체를 부르는 연결 (분대장)
- 탈출 장면, 갇힌 동료를 본 기억이 "봤다" → "여기 붙잡혀 있다"로 바뀌는 것, 심문 → 금기를 어긴 무게 → 회의까지의 인과 (졸병)
- 고기 국이 첫날 저녁에 열려 진실 줄기가 첫날 시작됐다. PT15에서 막혔던 곳이 풀렸다 (섬)
- 무기고가 상황을 읽었고, 방금 빗나간 상대 -1이 같은 판정을 되풀이하는 데 값을 매겼다 (섬)
- 버들마을에 닿고 10분 만에 수소문과 재회. 거절당한 뒤 "덮을 곳 없는 바깥"에서 야영하는 무게 (튜토리얼)
- 즉흥 이야기는 네 판 모두 쓰기 쉬웠다 (졸병·섬·튜토리얼)
- 장소의 사람을 target으로 부르면 들어오는 것, 이야기 배역이 이야기 뒤에도 남는 것이 GM 손을 덜었다 (세 판)
