# 의뢰 계획 (2026-11-24, 사용자 결정)

이야기 사이 간격(6~12시간, 여러 번 늘였다 줄였다 함)은 건드리지 않는다. 거점에서 이야기 없이 남는 시간을 채울 콘텐츠로 **의뢰**를 둔다. 보통의 RPG처럼 반복해서 받을 수 있는 일거리를 코드가 즉흥으로 만들고, GM은 연출만 한다 (원칙 2: 보상·기한·목표는 코드가 정한다).

배경: PT23에서 거점 안을 돌아다녀도 이야기가 드물었다(세 판). 장소별로 지금 조건이 맞는 이야기는 10~48편이라 장소 제한 탓이 아니고, 이야기 간격 탓이었다. 쓰지 않은 즉흥 자리가 간격을 잡던 것은 12-290에서 고쳤다. "다음 이야기 자리 알림"은 하지 않는다 (이야기 수를 늘리지 않고, 이야기를 노린 시간 맞추기만 부른다).

## 지금의 "부탁" (바꾸기 전)

- `content.scenario.promises.asks` (chance 0.3, max_open 2, expire_days 7): 날이 바뀔 때 30%로 만난 인물 하나가 인물 YAML `favors`의 부탁을 품는다(`promise_asked`). GM 상태에 "이 인물이 꺼낼 부탁"으로 뜨고 GM이 꺼낸다(`promise` accept/decline, 물건을 transfer_item으로 건네면 지킴)
- 종류는 물건 구해 오기 하나. 인물 37명에 1~2개씩. 한 번 한 부탁은 다시 안 나와 바닥난다
- 코드: `packages/core/src/engine/promises.ts`, 스키마 `favors` (`content/schemas.ts`)

## 정한 것 (권장안대로)

1. **부탁과 합친다.** 인물 YAML의 부탁은 "그 사람만의 의뢰"(글이 있는 것)로 남기고, 틀로 만드는 의뢰를 더한다. **진행 중인 의뢰는 한 번에 하나.** 임무(상관의 복무)와는 따로 센다 (임무 하나 + 의뢰 하나)
2. **받는 길.** 장면의 인물에게 "일거리 없나" 물으면 코드가 그 사람이 줄 만한 의뢰를 하나 만든다. 새 도구 하나 `request` (ask / accept / decline / report). 주는 사람에 따라 종류가 다르다(상인은 물건, 경비는 도둑 잡기, 의무병은 약 등). 지금처럼 하루 한 번쯤 먼저 꺼내는 부탁도 남긴다
3. **종류 넷.** 목표는 코드가 진짜로 만들어 세계에 둔다 (지어내지 않는다)
   - 찾아오기: 근처 구역 수색에서 나오는 물건
   - 사람 찾기: 근처 구역의 한 장소에 실종자 엑스트라를 둔다. 만나서 데려오거나 소식을 가져온다
   - 붙잡아 오기: 근처 구역에 무리 없는 악당 엑스트라를 둔다. 쓰러뜨려 묶어(bind) 데려온다
   - 처치하기: 감염체·짐승, 또는 무법자 (사람을 죽이는 의뢰는 무법자만. 행적·설정 거스르기는 지금 규칙대로)
   - 목표가 어느 장소에 있는지는 의뢰인이 아는 만큼만 (구역, 어림 단편 `placeHint`). 모르는 장소·단편 규칙(12-282·283) 그대로
4. **보상·기한·실패.** 시나리오 표(종류·거리·위험)로 코드가 셈: 물건, 무리 자원, 의뢰인과의 관계. 기한 며칠, 못 하면 의뢰인 신뢰 -1 (지금 부탁과 같음)
5. **콘텐츠.** 시나리오 파일에 의뢰 틀(종류, 주는 사람 조건, 보상 범위). 목표 엑스트라 틀은 대부분 있다(떠돌이 무리, 쫓기는 사람, 굶주린 감염체, 목줄 끊긴 개 등). 새로 "실종자"와 "무법자" 정도

복잡도: 새로 생기는 것은 도구 하나, 의뢰 기록 하나, 종류 넷. 부탁 규칙은 의뢰에 합쳐져 사라진다. 목표 두기는 엑스트라 만들기·장소(`movePlayer`가 아닌 엑스트라 자리)·묶기 등 지금 장치를 쓴다.

## 구현할 때 정할 세부 (구현 세션에서 권장안으로 진행, 바뀌면 사용자에게)

- 상태: `promises` 기록을 넓힐지(kind·target·zone·place) 새 `requests` 기록을 둘지 → 부탁과 합치므로 `promises`를 넓히는 쪽이 단순
- 공통 규칙 모듈: 의뢰 목표 판정(물건 지님·사람 만남·묶어 데려옴·죽음)은 한 모듈(예: `rules/request.ts` 또는 promises.ts 안)로, 다른 곳에서 직접 읽지 않게 guards
- 보상 표·기한·거리 계산은 시나리오 데이터 (core에 수치 하드코딩 금지, 원칙 7)
- GM 안내(prompts/mcp_play.md)와 상태 줄 ("진행 중인 의뢰", "이 인물이 꺼낼 의뢰")
- 테스트: 실제 콘텐츠로 종류 넷 각각 받기 → 목표 만들어짐 → 해내기·보고·보상, 기한 넘김, 하나만
- 문서: docs/design.md 12-291~ 행, 세이브 형식 올림
- 끝나면 PT24로 확인 (하네스, 다섯 판)
